## 一、为什么要做这一步

游戏内已经有完整的"半透明建筑渲染"实现：

| 状态 | 颜色 |
|---|---|
| 允许放置 | **浅蓝色**半透明 |
| 不允许放置（位置冲突） | **浅红色**半透明 |
| 已放置但**建造中**的建筑 | 也是**半透明** |

**这说明半透明渲染路径 + "可放/不可放"着色，游戏底层已经有了。**
我们投影渲染阶段 2 的目标是**复用这套机制，而不是自己造材质/造 pak**。

所以第一步不是写渲染代码，而是**先把游戏这套机制找出来、看明白**：
幽灵预览对象是什么类、它的半透明材质参数怎么控制、可放/不可放着色靠什么切换。

### F9（recon_ism）：渲染可行性与结构件 mesh 来源

**为什么需要**：渲染原型要用的 **ISM/HISM 分组渲染**，前提是 Lua 能触达世界的
ISM 组件；而结构件（墙/地板/屋顶）**没有独立 mesh**，很可能就是藏在某个
ISM 实例列表里（踩坑记录 3c-4b 的开放问题）。F9 一次性回答这两件事：

| 项 | 验证内容 | 对渲染的影响 |
|---|---|---|
| ISM 可达性 | `FindAllOf("HierarchicalInstancedStaticMeshComponent")` 等能否命中 | 命中 → Lua 能走 ISM 路线；不命中 → 渲染需另寻入口 |
| 读实例数 | `GetInstanceCount()` 是否绑定 | 绑定 → 能统计/遍历实例；未绑定 → 需换 API |
| 结构件 mesh 来源 | ISM 组件上的 `StaticMesh` 资产是否对得上结构件类型 | 对得上 → 可直接复用，免手写映射表 |
| 数据量预估 | ISM 汇总抽样（mesh + 实例数） | 评估渲染负载 |

**使用**：进世界后**直接按 F9**（不要求先进建造模式），输出 `recon_ism.txt`。

## 五（实测）。2026-09-26 第一轮侦察结果

> 已回填到 `docs/踩坑记录.md` **3f-2 节**。以下是最新实测结论。

### 实测结论摘要

| 假设 | 结果 | 说明 |
|---|---|---|
| H1 存在幽灵/预览对象类 | ❌ **全灭** | 10 个候选 `PalBuildObjectGhost`/`PalBuildSystem` 等全是 0 个。幽灵对象不在 `PalBuild*` C++ 类层级里，`FindAllOf` 枚举不到。可能藏 UMG/只在放置瞬间创建 |
| H2 `ForEachProperty` 能枚举属性 | ❌ 确认不可用 | 每次返回 `attempt to call a TrivialObject value (method 'ForEachProperty')`。与 3c-3 记录一致 |
| H4 材质在 `PalBuildObject` 上 | ❌ **不在 Actor 上** | 8 个材质字段（`Material`/`GhostMaterial`/`PreviewMaterial`…）全占位/空。材质/着色在**组件**或**下游对象**上 |
| H3 建造系统类 | ⚠️ 有新线索 | `PalBuildProcess` → **5786 个**（≈ `PalMapObjectModel` 5786 个，可能一一对应）。**"建造中=半透明"很可能就它控制** |
| ISM 可达性 | ✅ **可达** | `HISM` 515 / `ISM` 947 / `StaticMeshComponent` 13393 个；`GetInstanceCount()` **绑定成功** |
| 结构件 mesh 来源 | ⏳ 待定位 | 第一个 ISM 是水（`S_WaterMesh`）。需在 515 个 HISM 里**按 owner/mesh 过滤**出"建筑结构件"的 |

### 下一步侦察方向（第二轮）

1. **深挖 `PalBuildProcess`**：它是"建造中半透明"的最大嫌疑。试读它的组件/子对象/材质字段，
   看能不能找到 `SetMaterial`、透明度参数、或"建造状态 bool"。
2. **定位结构件 ISM**：枚举 515 个 HISM，过滤出 `StaticMesh` 资产或 `Owner` 类名
   带 `BuildObject` / `Foundation` / `Wall` 的，确认结构件 mesh 藏在哪。
3. **（可选）建造中的对象**：用户提到的"采石场预放置"正好是真实"建造中"场景——
   若能在放置采石场后对 `PalBuildProcess` 扫描，可能直接看到半透明状态。

### 回答用户的疑问（只预放置一个建筑有影响吗）

**不影响本轮结果的有效性**：`PalBuildObject`(651) 和 ISM 是持久世界对象，与\"当前预放置哪个\"
无关。但**若想捉到\"活的幽灵对象/建造中半透明\"**，需要换侦察方式——因为幽灵类名全灭，
不能再靠 `FindAllOf` 枚举幽灵。

## 六（实测）。2026-09-26 第二轮侦察结果

> 已回填到 `docs/踩坑记录.md` **3f-3 节**。PWRecon v0.8b，F8=recon_process / F9=recon_struct_ism。

### `PalBuildProcess` 只是状态容器，不持渲染数据

```
PalBuildProcess 共 5706 个
  #1: GetClass: /Script/Pal.PalBuildProcess   State = 1   （Mesh/Model/Material 全占位）
  #2: 同上
```

- 有 `State`（number）字段（1 = ？），但**没有 mesh、没有材质字段**。
- **结论**：`PalBuildProcess` = 建造"状态/进度"容器，「建造中半透明」的 mesh 渲染在别处。

### ★★★ 结构件 mesh 彻底定位：`BP_PalStaticMeshImposterChunk_C` + HISM

从 HISM 组件里过滤出结构件（前 8 个命中全挂在 ImposterChunk 上）：

| 资产路径 | count |
|---|---|
| `/Game/Pal/Model/Prop/Architecture/Architecture_Wood/SM_Floor_Wood` | 160/128/63 |
| `.../Architecture_Wood/SM_Roof_Wood` | 7 |
| `.../Architecture_Stone/SM_WallGate_Stone` | 1 |
| `.../Architecture_Wood/SM_WallWindow_Wood` | 4 |
| `.../Architecture_Wood/SM_Wall_Wood` | 7 |
| `.../Architecture_Wood/SM_Stair_Wood` | 1 |

**asset 命名规律**：`SM_<部件>_<材质>`，目录 `Architecture_<材质>/`。
**载体**：`BP_PalStaticMeshImposterChunk_C` 的 HISM。→ **游戏自己就用 HISM 批量画结构件**。
**渲染原型应照抄**：结构件 mesh 可直接建映射表，或用 ImposterChunk 里的 HISM 复用。

> ⚠️ 受单类扫描 200 上限影响，只确认了部分结构件 mesh。完整 79 种类型的
>   类型短名 ↔ `SM_<部件>_<材质>` 映射表仍需补全。

### 半透明材质的剩余去向

不在 PalBuildObject(Actor)、不在 PalBuildProcess(状态) → **最后两个嫌疑点**：
1. `PalBuildObject.Mesh`(StaticMeshComponent) 的**材质槽**（`GetNumMaterials`/`GetMaterial`）
2. `ImposterChunk` HISM 组件的**材质 override**（`.OverrideMaterials`）

## 八（实测）。2026-09-26 第三轮侦察结果

> 已回填到 `docs/踩坑记录.md` **3f-4 节**。PWRecon v0.8c，F8=recon_material / F9=recon_render_cap。

### ✅ 读材质槽 API 可用（半透明材质"真身"定位）

`GetNumMaterials()` / `GetMaterial(slot)` **绑定可用**：

- **功能设施**（`PalBuildObject.Mesh` 组件）：每个材质槽是 `MaterialInstanceDynamic`（MID）
  ```
  BuildableGoddessStatue: GetNumMaterials()=1, slot0=MaterialInstanceDynamic
  FarmBlockRecipe       : GetNumMaterials()=2, slot0/1=MaterialInstanceDynamic
  ```
- **结构件**（`BP_PalStaticMeshImposterChunk_C` 的 HISM）：`MaterialInstanceConstant`
  ```
  HISM slot0 =
  /Game/Pal/Model/Prop/Architecture/Architecture_Wood/Material/MI_PalProp_Floor_Wood
  ```

**asset 命名规律汇总**：
- mesh：`SM_<部件>_<材质>`，目录 `Architecture_<材质>/`
- 材质：`MI_PalProp_<部件>_<材质>`，目录 `Architecture_<材质>/Material/`

### ❌ 运行时创建组件：粗测失败，但疑为假阴性

```
全局含 Spawn/New/Component 符号: 只有 NotifyOnNewObject
_G.UGameplayStatics / _G.UWorld / _G.AActor -> 不存在
world:SpawnActor() -> 不可用(未绑定)
```

**关键**：`UGameplayStatics` 不在 `_G` **≠** 拿不到它。`UEHelpers.lua` 证实
`StaticFindObject("/Script/Engine.Default__GameplayStatics")` 可从引擎 CDO 调静态 UFunction。
所以"能否创建组件"**需用 StaticFindObject + CDO 路线深挖**（第四轮专门做）。

### 🎨 用户实测的半透明机制（对渲染设计影响大）

- **预览/放置**：所有建筑（功能+结构）都半透明
- **建造中**：仅部分功能建筑有；结构建筑放置即生效
- **建造中视觉**：浅蓝半透明 → 随进度**从底部往上替换为黄色**半透明 → 完成=真色
- → 游戏用的是**竖直方向 alpha/遮罩**的半透明材质（MID 参数控制），正是分层投影想要的机制。
