## 0. 三条贯穿全项目的铁律

| 铁律 | 含义 | 落到代码 |
|---|---|---|
| **① 分层: 策略层不碰引擎** | 按键回调/策略纯 Lua；碰引擎一律经"通道层/引擎层" | `pwpr_notify.lua`（策略）→ `pwpr_hud.lua`（通道）；`pwpr_sched.lua` 把工作丢回**游戏线程** |
| **② 只读的不怕，写对象要门禁** | 采集/对齐/扫描是**只读**；只有投影渲染会**创建/修改**引擎对象 | `pwpr_ghost.lua` 是唯一"写对象"的模块，进它之前有**双重门禁** |
| **③ 任何引擎调用都单独 `pcall`** | 一次失败只影响那一条数据，绝不级联 | 全项目；另外**原生访问违例 `pcall` 抓不住** ⇒ 所以还有"不碰死对象"的纪律（见 §9） |

## 2. 蓝图采集（按 `Y`）—— **纯只读 + 写 JSON**

`pwpr_capture.lua` → `pwpr_bp.lua` → `blueprints\*.blueprint.json`

| 步骤 | 做法 | 用到的接口 |
|---|---|---|
| ① 列建筑 | 先拿 `World.PersistentLevel.Actors` **全表**，按**类链**筛 `PalBuildObject`；拿不到才退回 `FindAllOf("PalBuildObject")` | `Util.find_world`、`class_chain_has` |
| ② 位置/朝向/类型 | 逐件读 | `K2_GetActorLocation()`、`K2_GetActorRotation()`、`GetClass():GetFullName()`（类型名 = 去 `BP_BuildObject_` 前缀与 `_C` 后缀）|
| ③ 网格资产 | 功能设施从 actor 上读；**结构件（地基/墙/屋顶）在 actor 上读不到** ⇒ 扫世界上的 ISM 组件、从**组件全名**反解 `BP_BuildObject_<类型>_C` | `obj.Mesh.StaticMesh:GetFullName()`；`pwpr_meshmap.lua` |
| ④ 组织成蓝图 | 原点吸附到网格、按 Z 聚类**分层**、算包围盒与统计 | `BP.*`（纯 Lua）|
| ⑤ 落盘 | JSON（带 BOM，记事本不乱码）+ 网格覆盖表 `pwpr_meshes.txt` 供补映射 | `Util.write_file` |

* **只读纪律**: 该文件里 `SpawnActor` / `SetMaterial` 出现 **0 次**；每一步单独 `pcall`。
* 采集**不创建 actor、不改材质、不借用任何已有对象**。

## 3. 投影渲染（按 `K`）—— **自己的宿主 + 自己的实例化组件**

`pwpr_ghost.lua`（进它之前：`ghost_enabled = true` **且** `pwpr_capabilities.json` 里有探测通过记录）

| 环节 | 做法 |
|---|---|
| **宿主** | `World:SpawnActor(Engine.Actor)` 生成一个**空 Actor** 当宿主（不复用、不借用任何游戏 actor）|
| **组件** | **每个"网格资产"一个** `InstancedStaticMeshComponent`（一个基地 60~80 个组件，不是"每件建筑一个"）；`SK_*` 骨骼资产用 SkeletalMeshComponent（`SetSkinnedAssetAndUpdate`）|
| **实例** | 用**局部坐标**（蓝图相对厘米）`AddInstance(tf, false)`；组件承载"放置变换"⇒ 挪投影 = 改 60~80 个组件的 `K2_SetRelativeTransform`（不重建几千实例）|
| **材质** | 取**游戏自带**的 `BuildingSurfaceMaterialSet.Highlight`（失败退回备用 `MI_*`），用 `comp:SetMaterial(slot, mat)` 设到**我们自己的组件**上（可用 `MUL` 键循环 4 档）|
| **碰撞/阴影** | `SetCollisionEnabled(0)`、`SetGenerateOverlapEvents(false)`、不投影阴影、`SetMobility(2)` |
| **分层** | `L` 换一批实例（`ClearInstances` + 重新 `AddInstance`），数据层只是过滤 |
| **两条变换路径** | ① **便宜路径**: 只 `apply_transform`（微调/挪动）；② **完整重灌**: `fill`（重建实例 + 重算名单）⇒ `H`/`U`/`K` 走完整重灌，方向键微调走便宜路径（**这是踩过的坑**，见 `踩坑记录.md` §44）|
| **粒度** | 「已放上」变化时用 `Ghost.rehide(records)` **只重灌受影响的组件组**，不整体重建 |

## 4. 「已放上」的件不再画 —— **只有两个来源**

`pwpr_placed.lua` + `pwpr_ghost.lua` 的 `Ghost.skip`

| 来源 | 机制 |
|---|---|
| ① **精确通道** | 吸附时我们就知道"这一件对应哪条记录"（`rec_idx`）⇒ 立刻把它记进名单（`Ghost.skip`），重灌时**不加它的实例** |
| ② **记录进度** | `pwpr_placements.json` 里那一处 sites 的 `placed` 列表（下次按 `K`/`U` 沿用）|
| **兜底扫描** | `Placed.refresh`: 读**真实建筑**的坐标，一对一贪心认领（一个实物只认领一条记录），**只减不增**（不会凭空认领别处的建筑 ⇒ 这是 §39/§40 的教训）|
| **增量更新** | 名单变了 → `Ghost.rehide(delta)` 只动受影响的组；放置用**批量窗口**（默认 3 秒）合并成一次 |
| **为什么不用"查引用还在不在"当主路** | 那要对 `level.Actors` 里**已摧毁**的 actor 调引擎函数 ⇒ **原生访问违例，`pcall` 抓不住**（崩过）⇒ 默认关（`ghost_hide_alive_check`）|

## 5. 位置 / 进度记忆（`pwpr_resume.lua` + `pwpr_placements.json`）

| 概念 | 做法 |
|---|---|
| **sites** | 一张蓝图 = 多"处"记录（每处 = 锚点 x/y/z + yaw + 偏移 + 蓝图尺寸 + `placed` 进度）|
| **两个半径** | **沿用/找当前处** = 蓝图包围盒一半 + `ghost_resume_margin_m`（宽，≈53 米）；**登记/写回** = `ghost_site_merge_m`（10 米，收紧，保证"换个地方建 = 新的一处"）|
| **距离** | **只用水平距离**（z 不参与）⇒ 楼上/楼下算同一处（`已知限制.md` 有记）|
| **落盘** | 内存记账；每 `resume_save_interval_s`（10 秒）/ 收起投影 / 攒够 20 次改动写一次（**不是每次放置都写盘**）|
| **切换** | `U` 在这张蓝图的多处记录间切换（创建顺序）；`H` = 在脚下放**全新一份**（不查范围、完整重灌）|
| **工具** | `tools\resume_tool.py`（list / drop-site / drop-progress / drop-blueprint / drop-all，`--dry-run`）+ `tools\resume_sim.py`（模型离线复刻）+ `tools\check_resume_json.py`（与 Lua 模板字段一致性）|

## 6. 建造吸附与落位（`pwpr_buildsnap.lua`）—— 唯一"改游戏行为"的功能

完整细节 + 实测记录见 `docs\建造吸附.md`；这里是实现骨架：

| 步骤 | 做法 |
|---|---|
| ① **挂钩** | `RegisterHook("/Script/Pal.PalNetworkPlayerComponent:RequestBuild_ToServer", pre, post)`（`pre_id=9 post_id=10`）|
| ② **读参数** | `RemoteUnrealParam`/`LocalUnrealParam` **必须先 `unwrap` 再读**（`read_name_string`/`read_vec3`/`read_quat`）|
| ③ **选目标** | 按类型（含**归一化名 + 公共前缀 ≥4 的同义层**、放宽层、学到映射）挑最近的记录；**距离判据**: 高度差 ≤ 人物半高（88cm）时用**平面距离**，否则三维 |
| ④ **拦下原请求** | 把 id 参数 `set(FName("None"))` 并**回读校验**（读不回 `None` 就当没拦住 ⇒ 原样放行）|
| ⑤ **重发** | 用普通 Lua 表 + `FName` 再发一次；**默认排到下一帧**（`buildsnap_defer`：`Sched.game_thread(fn,0)`，干净调用栈）|
| ⑥ **落地确认** | `NotifyOnNewObject("/Script/Pal.PalBuildObject")` 先进先出认领；1.2 秒内没新建筑 = 游戏拒了 ⇒ 撤销隐藏 + 记录 |
| ⑦ **自适应/降级** | 被拒且改过高度 ⇒ `deps.on_z_rejected` 把**整份投影高度**挪 `dz`（弹提示 + 记进位置记忆）；挪不了/再被拒 ⇒ 本次会话内该类**只吸 x/y** |
| ⑧ **记忆（只记录）** | 崩溃/卡死 ⇒ 黑匣子"有登记没返回" ⇒ 下次启动写日志/`F7`，**不改变行为**（`AGENTS.md` 规矩 3c）|
| ⑨ **安全** | 整体 `pcall`；异常只记日志；`buildsnap_enabled`（`F8` 即时）/`buildsnap_dry_run`（干跑）/`buildsnap_defer`（回旧路）|

## 7. 投影对齐（`snap_key`，默认不绑键）

`pwpr_snap.lua`：**只读**参照 + 投票

1. 读本关卡活着的 `PalBuildObject` 的**位置/类名/actor 朝向**（**故意不读网格组件** —— 老存档里被删的网格是野指针）；
2. 每条蓝图记录找最近的**同类**参照（阈值 `snap_radius_cm`）；
3. **朝向投票**（参照朝向 − 记录朝向，票最高几个 + "不动"候选）；
4. **偏移投票**（三维候选点按 25 厘米分格投票 → 最高票格内平均）；
5. **复核**（朝向候选 × 偏移候选 → 有多少条记录能对上，取最高分）；
6. 至少对上 `snap_min_matches` 件才接受，否则**一动不动**只报原因。
⇒ 只改**我们自己投影的偏移**，不动任何游戏对象。

## 8. 屏幕提示（`pwpr_notify.lua` 策略 + `pwpr_hud.lua` 通道）

三层：**策略层**（何时发/发什么/节流；纯 Lua）→ **通道层**（真正送到画面）→ **探测层**（`O` = S9，结果写 `pwpr_ui.txt`）。

| 通道 | 实现 | 状态 |
|---|---|---|
| `console` | UE4SS 窗口 `print`（ASCII 化）| 永远可用（**未探测时就是它**）|
| `notice_text` | **自建浮层控件**: 拿游戏自带的控件类 `WBP_Warning_LowMemory_C` 实例化一份自己用 → 对它内部的 `TextBlock:SetText` | 中文能显示；`notify_allow_borrow=false` ⇒ **不动游戏原有 UI** |
| `client_message` | `PlayerController:ClientMessage` | 🔴 **永久禁用**（实测调用即 `EXCEPTION_ACCESS_VIOLATION`）|
| `named_call` | 按配置 `notify_func` 指定的函数名调**游戏反射出来的**方法，只传 1 个字符串 | 可选、默认关 |

* 自建控件步骤（取类 → `WidgetBlueprintLibrary:Create` → 找文本子控件 → `SetText` → 沿父链显示 → 定时隐藏）见 `屏幕提示功能.md` §四。
* `F7` 那张按键表来自 `pwpr_notify.lua` 的 `Notify.KEYS`（**单一来源**）。

## 9. 安全设计（为什么它几乎崩不了游戏）

| 机制 | 说明 |
|---|---|
| **分阶段激活** | 能力探测（`N`）把"这台环境能不能做"写成 `pwpr_capabilities.json`；投影**双重门禁**: `ghost_enabled` + 探测通过记录 |
| **只读 vs 写对象分离** | 只有 `pwpr_ghost.lua` 会创建/修改对象；其余全是只读或纯 Lua |
| **游戏线程纪律** | 只要碰引擎就走 `Sched.game_thread`（热键回调不一定在游戏线程上）|
| **`pcall` 纪律** | 每个引擎调用单独 `pcall`；**但原生崩溃抓不住** ⇒ 另有纪律: 不碰"可能已销毁"的对象（`level.Actors` 会留死对象）|
| **禁用接口表** | `KismetSystemLibrary:PrintString`（Shipping 里函数体被编译掉）、`PlayerController:ClientMessage`（调用即崩）、`ForEachFunction/ForEachProperty/ForEachUObject`（调用即崩）—— 即使"反射里有/签名公开"也**不许调** |
| **跨世界清理** | `LoadMapPre` 钩子只**丢引用**、不碰引擎（防跨世界野指针）|
| **开关齐全** | `F8` 即时生效的开关 + 干跑 + 记忆重置（删 `pwpr.log`）+ 配置迁移 |

## 10. 日志与取证（出问题时的第一手证据）

| 机制 | 说明 |
|---|---|
| `pwpr.log` | **缓冲 + 攒批落盘**（攒 200 行 / 隔 5 秒）⇒ 平时零开销，**但卡死时会丢最后一段** |
| **`Log.solid`（黑匣子）** | 放置路径的关键步骤**同步 append 落盘**，不走缓冲 ⇒ 卡死/崩溃现场也留得下证据 |
| 黑匣子行 | `● 钩子被调用` / `● 请求 #N id=… 附加参数=…` / `● 即将拦原请求` / `● 拦截结果` / `● 重发前 id=… 改高度=…`（**延后**时写明）/ `● 重发返回` / `● 干跑（不改游戏）` |
| 崩溃/卡死记忆 | "有 `● 重发前`、没有 `● 重发返回`" = 上一次出事的点；启动时读**日志尾部 512 KB**，写一行 `● 记忆 frozen id=… stage=…`（以后每次启动重新登记，防止被挤出窗口）；**重置 = 删 `pwpr.log`** |
| 判读顺序 | 见 `当前行为总览.md` §7 与 §7b（含"最后一行 `●` 就是卡死位置"的表）|

## 11. 配置与迁移（`pwpr_config.lua`）

* `DEFAULTS`（带注释的默认值）+ `Config.KEY_GROUP`（1=正在起作用 / 2=诊断 / 3=历史遗留）+
  `MIGRATIONS`（版本迁移）+ `CONFIG_VERSION`（改默认值就 +1，老配置里的旧值会被迁到新语义）。
* 配置文件只写"和默认值不同"的键；`F8` 即时重载。
* 强制自检: `python tools\check_config_doc.py`（每个键都要在 `配置说明.md` 里、每个配置文件都要被点名）。
