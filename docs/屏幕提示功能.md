# 屏幕提示（游戏内文字提示）—— 功能说明与实现记录

> 整理时间: **2026-09-28**
> 状态: **✅ 实机可用**（正常操作会在游戏内左上角显示中文提示，约 10 秒后自动消失）
> 对应待办: `docs/项目状态与路线图.md` 的 **待办 1**
> 踩坑全过程: `docs/踩坑记录.md` §19 ~ §24

---

## 一、玩家看到的是什么

* 任何操作（采集 / 加载 / 放置 / 微调 / 切层 / 探测…）→ **屏幕左上角出现一行中文**。
* 提示**约 10 秒后自动消失**（`hud_seconds` 可改）。
  * ★ 计时从**提示显示出来的那一刻**起算（`ExecuteInGameThreadWithDelay` 延迟回调）。
  * 所以：**加载(`J`)/投影(`K`)的提示在操作完成后才发 ⇒ 卡顿不算在内**；
    **采集(`Y`/`U`)的提示在"网格注册表导出"之前发 ⇒ 那几秒算在内**
    （导出超过 `hud_seconds` 时，提示会"刚出现就被收走"）。
  * ✅ **2026-09-28 已修**：采集流程在**导出结束之后**补一次 `Notify.resend()`
    —— 把最后一条提示**重发并重新计时**（约 60ms 的 SetText 开销）。
    于是"采集完成"既立刻有反馈，又能在卡顿结束后**完整停留 `hud_seconds`**。
* 出处：**我们自己创建的一个游戏浮层控件**（不是游戏的通知系统）。
  用的是游戏自带的"内存警告条"控件 `WBP_Warning_LowMemory_C` 的类，
  **红字、左上角** —— 颜色目前不可自定义（见"已知问题"）。

## 二、三层结构（改动时先看清在哪一层）

```
pwpr_notify.lua   策略层: 什么时候提示、提示什么、节流；按键表(Notify.KEYS)
      │   Notify.show(中文, 英文, kind)
      ▼
pwpr_hud.lua      通道层: 把一行字真正送到画面（自建控件 / 控制台）
      │   Hud.show(text, ascii, kind)
      ▼
pwpr_probe.lua    探测层: 按 O 时检查"哪些通道可用"，并写出 pwpr_ui.txt
```

设计原则：**策略层不碰引擎，通道层只干"送字"这一件事。**
（原因：调用方里有 `on_direct` 的纯 Lua 按键处理器，在那些路径上读引擎是早期崩溃的成因类别。）

## 三、通道表（`Hud.CHANNELS`）

| 通道 | 状态 | 说明 |
|---|---|---|
| `console` | ✅ 永远可用 | UE4SS 控制台 `print`。**零风险**。能否看见取决于 UE4SS 的 `GraphicsAPI` 设置（`opengl` 时控制台是独立窗口，不覆盖游戏） |
| `notice_text` | ✅ **当前使用** | 自建控件 + `TextBlock:SetText`。**中文能显示** |
| `client_message` | 🔴 **永久禁用** | `PlayerController:ClientMessage` —— 实测**调用即闪退**（`EXCEPTION_ACCESS_VIOLATION`）。已标 `never_call`，连探测都不许调它。详见踩坑记录 §21 |
| `named_call` | ⚠️ 默认关 | 通过 `notify_func` 配置指定函数名、只传 1 个字符串参数。高风险（未验证参数个数） |

> **判断通道可用性的唯一标准是实机调用证据。**
> "反射里有 / `usable=true` / 签名公开 / 别人的代码里写过"**都不算证据**
> —— 本项目被这条误导过三次（`IsValid` / `ForEachProperty` / `ClientMessage`）。

## 四、自建控件的做法（代码自己写）

> 🔴 **勘误（2026-09-29，SBB 作者本人更正）**: 下面两行原话
> 「关键转折：读了 SBB 的源码」「它左下角那条进度提示是**它自己的 UMG 控件**画的，不是游戏接口」
> —— **后半句是错的**。SBB 作者说他是**调用游戏自己反射出来的消息显示接口**
> （**左下角滚动消息 + 顶部警告消息**两类）。
> ⇒ 我们"自建控件"这条路**不是因为 SBB 这么做**，而是**我们自己试过的通道都不行**：
> `PlayerController:ClientMessage` 实测**一调用就闪退**（`EXCEPTION_ACCESS_VIOLATION`，踩坑记录 §21），
> 游戏那个"半透明预览/通知对象"又 Lua 抓不到 ⇒ 才选了
> "**拿游戏自带的控件类（`WBP_Warning_LowMemory_C`）实例化一份自己用 + `TextBlock:SetText`**"。
> ⇒ 以后若想换成游戏原生那条: 方向是**找那个"反射出来的消息函数"**（SBB 作者已证明存在），
> 而不是继续找控件。

```
1) 取类:    从"配置指定的类的活实例"上 GetClass()
            （不要用 StaticFindObject 拿组件类 —— 会拿到 TrivialObject 假对象）
2) Create:  WidgetBlueprintLibrary:Create(pc, cls, pc)
3) 挂载:    AddToPlayerScreen(50)   —— 首选（失败退 AddToViewport(50)）
4) 取文本框: ① 直接读属性 instance.<子控件名>
            ② GetWidgetFromName(FName(名))
            ③ 扫描差集（新建出来的文本控件）
5) 写字:    TextBlock:SetText(FText("中文"))
6) 强制可见: SetVisibility(3 = 命中测试不可见) + SetRenderOpacity(1)
            + 顺父链向上把每一层都点亮（有浮层的内容容器默认是折起的）
            + 根控件一起处理
7) 定时收起: 10 秒后 SetVisibility(1 = 收起)
8) 清理:    RemoveFromParent + RemoveFromRoot（NUM 1 紧急出口 / F8 换配置）
```

### 为什么必须"复制一个天生就是浮层的控件"

| | 正确做法 | 曾经的错误 |
|---|---|---|
| 复制的控件 | 游戏自带的**独立浮层**（`WBP_Warning_LowMemory_C`） | `WBP_Notice` —— **通知列表里的一项** |
| 结果 | 正常显示 | 在视口里 / 不透明 / 期望尺寸 456×40 / 回读正确 —— **就是看不见** |

列表项的布局**依赖父容器**（列表槽位）；单独挂到屏幕上没有父容器给它尺寸和位置，
整棵子树就画不出来。**"属性全对却看不见"的根因就是这个。**

## 五、配置项（`Scripts\pwpr_config.json`，改完按 `F8` 即时生效）

| 键 | 默认 | 作用 |
|---|---|---|
| `hud_enabled` | `true` | 屏幕提示总开关 |
| `notify_own_widget` | `true` | 是否用"自建控件"这条路；`false` = 只走控制台（**应急开关**，完全不碰 UI） |
| `notify_widget_class_name` | `WBP_Warning_LowMemory_C` | 复制哪个控件类 |
| `notify_widget_text_child` | `Text_Warning` | 里面那个文本框的子控件名 |
| `notify_error_class_name` | `""` | **留空 = 不单独维护第二套**（出错也走上面那条） |
| `hud_seconds` | `10.0` | 提示停留几秒 |
| `notify_autohide` | `true` | 是否自动消失 |
| `notify_min_interval` | `0.25` | 节流：同一时间窗内只发第一条 |
| `notify_allow_borrow` | `false` | 是否允许"借用游戏自己的文本框"（**默认关**：不动游戏原有 UI） |
| `notify_style_retry_s` | `60` | 样式创建失败后多久不再重试（避免反复造坏控件） |
| `notify_send_telemetry` | `false` | 发送时是否附加诊断信息（会多调约 10 次引擎接口） |
| `notify_scan_in_send` | `false` | 发送时是否允许遍历全局文本控件表兜底（**默认关**：那个遍历是崩溃嫌疑） |
| `hook_load_map_pre` | **`true`** | ★ **换地图时丢弃跨世界引用**（LoadMapPre 钩子）。它是"回标题 → 重进世界闪退"的**正解**，别关 |
| `world_guard_enabled` | `false` | **已废弃**（保留只兼容旧配置）：轮询世界标记现在只做诊断、不影响行为 |

> ★ 配置文件的写盘规则（2026-09-27 改）: **只写"和默认值不同"的项**。
> 所以文件里没有的键 = 用代码里的默认值；我们以后改默认值，玩家会自动跟着变。
> （老实现把全部默认值写进文件，导致"改了默认值但玩家不生效"的坑咬了四次。）

## 七、出问题怎么查（排查手册）

1. **看 `Scripts\pwpr.log` 末尾**：发提示的每一步都有 `[ns]` 标记，落盘即写。
   * `[ns] 开始` → `FText 好了` → `取控件[normal]` → `找文本框` → `SetText 完成` → `force_display 完成`
   * 崩在哪一步，日志最后一行就是答案。
2. **看 `Scripts\pwpr_ui.txt`**：按 `O` 生成的完整探测报告
   （通道可用性、候选控件、本次发送实况、通道状态）。
3. **看 `UE4SS.log`**：`>> 动作名` / `<< 动作名` 包住每次按键处理
   （能判断"崩在哪个按键、有没有走完"）。
4. **`F7`**：游戏内查看状态与最近发出的文字。
5. **应急**：`notify_own_widget = false` + `F8` ⇒ 提示只进控制台，UI 零风险。

## 八、已知问题（截至 2026-09-28）

| # | 问题 | 现状 / 绕法 |
|---|---|---|
| 1 | **颜色不可自定义** | `_G.FLinearColor` / `_G.FSlateColor` 都**没有暴露**给我们，构造不出 `SetColorAndOpacity` 要的结构体。所以颜色只能由"用哪个控件"决定。换控件类是改配置即可 |
| 2 | ~~"回标题 → 重进世界"后第一次操作可能闪退~~ → **已修（2026-09-28）** | 根因: 上个世界的对象已销毁，而 `Util.usable()`/`IsValid()` 会**撒谎**（返回 true），于是拿废控件去 `SetText`。**修法: 用 `LoadMapPre` 钩子做"权威信号"** —— 引擎说"要换地图了"时，**只清 Lua 引用、一个引擎接口都不碰**（`Ghost.forget` + `Hud.drop_world_refs`）。轮询世界标记降级为**纯诊断**（它抖动时曾把正常放置搞坏: 每次 0 件）。开关 `hook_load_map_pre` **默认 true，别关** |
| 3 | 只有一种样式 | `notify_error_class_name` 留空 ⇒ 正常/出错共用一条。想区分就填上另一个控件类 |
| 4 | `WBP_Ingame_Sleep_C` / `WBP_IngameSmesTop_C` 实测也能显示 | 但前者是"睡眠框"、后者像"升级提示"，观感不对 ⇒ 不用 |
| 5 | 提示不排队 | 新提示直接覆盖旧提示（旧定时器会作废，保证新提示拿到完整时长） |

## 十、以后想改的话，先看这几条

1. **改外观**：换 `notify_widget_class_name` + `notify_widget_text_child`（配置即可）。
   候选控件必须是**独立浮层**，且名字要能从活实例的控件树里读到。
2. **改时长/节流**：`hud_seconds` / `notify_min_interval`（配置 + `F8`）。
3. **加新提示**：在代码里调 `Notify.show("中文", "ascii", "error"?)`
   —— 失败类用 `"error"`，普通反馈省略。
4. **别碰的**：`KismetSystemLibrary:PrintString`、`PlayerController:ClientMessage`、
   `ForEachFunction/ForEachProperty/ForEachUObject`（都实测崩游戏，且检查器有拦截）。
5. **修"重进世界"那个 bug 的顺序**：先让**世代标记稳定**（或改成
   `hook_load_map_pre` 事件驱动），再打开 `world_guard_enabled` 单独验证。
6. **改完一定跑**：`python tools\luacheck.py mod\PWProjection\Scripts`
   （15 项静态检查里第 10/11 项专门拦"保留字当字段名"和"禁用的反射枚举"）。
