## 0. `Scripts\pwpr_placements.json` —— 投影位置 + 进度记忆（**自动生成，一般不用手改**）

> 记住「**每张蓝图、每一处：投影放在哪 + 已经建到哪**」，
> 这样「上次没建完 → 退出游戏 / 换蓝图 → 回头继续建」时，按 `K` 可以**沿用上次的位置**，
> 而且**已经建好的那部分直接不画**（= 接着上次的进度建）。
>
> ★ **一张蓝图可以有多处记录**（`sites` 列表）—— 你在 A 处放过、又在 B 处放过，两处都留着；
> 按 `K` 时自动挑「你所在的那一处」（按包围盒 + 容许距离判定，命中多处取最近的一处）。
> 每处记这些: 锚点 `x/y/z` + 朝向 `yaw` + 你的微调 `ox/oy/oz` + **蓝图尺寸 `sx/sy/sz`**
> + **进度 `placed`**（已放上的记录序号列表）。
>
> * ★★ **记录到底是怎么产生的**（玩家三轮实测后定稿）:
>   **只有「真在这一片放下过建筑」才会产生一处记录**（记录 = 那一处的位置 + 朝向 + 微调 +
>   蓝图尺寸 + **那一片的进度**）。
>   * 光按 `K` 放投影、光按 `H` 挪到脚下、只用方向键微调 —— **都不会产生记录**
>     （`H` 只在「这一片已经有记录」时更新它的位置）；
>   * 一旦你在这里**真放下建筑**，就会自动记下这一片（日志里有一行
>     `[resume] 新增一处记录（第 N 处，M 件进度）`）；
>   * 于是既不会「随手挪几下投影就冒出好几条记录」，也不会「进度跑到别的基地去了」
>     （**进度只属于它所在的那一片** —— 实测两个锚点可以相距 4.7 公里）。
> * ★★ **"已经放上的不画"这份名单是跟着位置走的**（2026-09-29 第四轮实测后定稿）:
>   把投影放到/挪到某处时，名单会**重新对齐到那一片的记录**：
>   那一片有记录就加载它的进度，**没有就清空**。
>   所以不会出现"在 A 建过的东西，到了 B 的投影里也看不见"这种跨位置串味。
> * 按 **`U`** = 在这张蓝图的多处记录之间循环切换（`B` 是**游戏自己的建造模式入口**，我们用不了）。

| 行为 | 说明 |
|---|---|
| 什么时候写 | **不是每次放置都写**（玩家明确要求）：放置/微调只改内存，**每 10 秒**（`resume_save_interval_s`）批量落一次；另外**收起投影、按 `F8`、攒够 20 次改动**时立刻落一次 |
| 哪些情况会沿用 | 你**还处在"上次那片蓝图范围"内**（蓝图包围盒 + `ghost_resume_margin_m`，默认 20 米）时才沿用 ⇒ 换存档/去别的基地不会误用。<br>**判定是按"蓝图范围"而不是"离锚点多远"**：锚点只是"上次按 K 时你站的位置"，而基地往往比它大得多 ⇒ 按范围判定才能"站在基地任何一角都算数" |
| ★ 进度不会被"空扫描"洗掉 | 按 `K`/`H` 重放投影时会**扫一遍真实建筑**再算"哪些已经放上了"。如果这次**一件参照都没扫到**、或者**扫到了但一件都没配上**（类型/网格对不上），
| | 就**保留上一次的名单**（不清空）并在日志里写明 —— 以前那里会直接清空，导致"切回原来的位置，建过的又全画出来了"。真要清就 `tools\resume_tool.py drop-progress` |
| 进度也会记下来 | 记着一份"**已经放上的记录序号**"；下次加载同一张蓝图时**立刻**恢复（已建好的那部分不画），随后按 `K` 放投影时的全扫会按**当前世界真相**再核对一遍（拆掉的会重新画出来）⇒ 记住的进度只是"更快的起点"，不会变成错的真相 |
| 怎么拒绝沿用 | 按 **`H`**（"重新定位到脚下"，本来就是它） |
| 想全部忘记 | 删掉这个文件即可（游戏下次会重新生成） |
| ★ **怎么删一部分**（玩家 2026-09-29 问「如果我要删掉这些记录应该怎么搞」） | 见下面那一段 |
| 容量 | 每张蓝图最多 **8 处**；总蓝图数上限 **200**；蓝图很多时最旧的先丢 |

> 你在外面删了也会被覆盖回去。

| 想删什么 | 怎么做 |
|---|---|

## 1. `Scripts\pwpr_config.json` —— 主配置

### 怎么改

| 步骤 | 说明 |
|---|---|
| 1 | 打开 `<mod>\Scripts\pwpr_config.json` |
| 2 | 按下面的键名加/改一行（JSON 格式） |
| 3 | 游戏里按 **F8** 即时重载（不用重启游戏） |

> ### ⚠️ 加新键时**必须写在同一个 `{}` 里面**（2026-09-29 补，玩家踩过）
>
> 文件是**一个** JSON 对象。想加一个键，就加在**第一个 `{` 和最后一个 `}` 之间**，
> 记得**给上一行补个逗号**:
>
> ```json
> {
>   "ghost_enabled": true,
>   "buildsnap_mode": "align",      ← 新加的行写在这里（注意前一行的逗号）
>   "config_version": 8
> }
> ```
>
> ❌ **不要另起一个 `{}`**:
>
> ```json
> { "ghost_enabled": true, "config_version": 8 }
> { "buildsnap_mode": "align" }      ← 错: 这是第二个 JSON 对象
> ```
>
> * 这种写法以前会让**整份配置**解析失败、**所有设置一起退回默认值**
>   （连 `ghost_enabled` 都掉回 `false`、投影被锁），而游戏里只表现为"我的配置没生效"；
> * **现在会容忍**: 多个 `{}` 会自动**合并**（后面的覆盖前面的），
>   并在启动日志 / `F8` 重载日志 / `F7` 状态里**大声提示**你写法不对 ——
>   但请顺手改成上面对的那种写法，别一直依赖容忍。
> * **最省事的办法**: 改完按一次 `F8`，让本 mod 自己把文件重写成规范格式
>   （它只写"和默认值不同"的键，都在同一个 `{}` 里）。

**文件里的 `_readme` / `_section_1..3` 是代码写出来的分组标题**（下划线键会被忽略），
只是为了让文件自己解释自己。只有**和默认值不同**的键才会出现在文件里
（这样我们改默认值时，你的配置不会压住新默认值）。

**代码维护的键（不要手改）**：

| 键 | 含义 |
|---|---|
| `config_version` | 配置结构版本。代码升级时靠它做迁移（把老配置里的旧键补/改成新语义），**手改会导致迁移跑错** |

#### 0.4b 怎么判断"附近有没有已经存在的记录"（2026-09-29 定稿）

**一句话**: 拿**现在投影的锚点**和记录里存的**锚点**比**水平距离**（只用 x / y，**忽略高度 z**），
按用途分**两个半径** —— **"沿用"宽、"登记"紧**：

| 用途 | 半径 | 为什么 |
|---|---|---|
| **按 `K` 沿用** | **蓝图包围盒一半 + `ghost_resume_margin_m`**（这张蓝图 ≈ 53 米，宽）| `K` 的语义是"对齐到这个世界" —— 站在基地**任何角落**按 `K`，都应该认出"我在哪一处"并沿用它的位置 + 朝向 + 偏移 + 进度 ✓ |
| **放建筑时写回进度（登记）** | **`ghost_site_merge_m`**（默认 **10 米**，紧）| 只有"就在这一处旁边"才算同一处；换个地方建 ⇒ **新的一处** ✓（用宽半径会让"换个地方建"被并进几十米外的旧记录 ✗ = 曾经的"回填到旧位置"bug）|
| **按 `U` 换一处** | 不看距离 | 按**创建顺序**依次切到每一个登记过的位置 |
| **按 `H` 重新放一份** | **完全不查** | 直接把投影放脚下、名单清空 ⇒ **一份完整的新投影** ✓ |

**命中多处** ⇒ 取**水平距离最近**的那一处。

**为什么"登记"要用 10 米这么紧**: 蓝图包围盒可能有几十米（这张 66 米）⇒ 用它当登记半径时，
"同一个基地里换个位置建"会被并进同一处 ⇒ A/B 的进度互相串（2026-09-29 实测踩过 ✗）。
**"沿用"和"登记"分成两个半径**，语义就各归各位了 ✓

**取舍（要知道的）**:
* 判定**忽略高度** ⇒ 同一个 x/y 但不同高度（楼上/地道）会被当成**同一处**。想区分就把
  `ghost_site_merge_m` 调小（登记）并把 `ghost_resume_margin_m` 也调小（沿用）；
* 想让"一整片基地 = 一处、站哪都算同一处" ⇒ 把 `ghost_resume_margin_m` 调大（例 `50`）✓；
* 想在基地里"每换一次位置就记新的一处" ⇒ 把 `ghost_site_merge_m` 调小（例 `3`）✓

> ★ 历史: 2026-09-29 一度把"沿用"也收紧到 10 米（为了让 `H` 的完整投影不被随后按 `K` 撤销 ✗）——
> 那是 `H` 本身没做完整重灌导致的（见 `踩坑记录.md` 的"省事路径"那条）。`H` 修好之后，
> "沿用"就该是宽的：**`K` = 对齐世界（沿用）、`H` = 全新一份（不查）** ✓

| `ghost_resume_margin_m` | `20` | ★ **只影响「沿用」（按 `K`）**：蓝图包围盒之外再放宽的距离（米）—— 站在范围边上再往外 20 米内也算「还在原地」。<br>**不影响「登记」**（那看 `ghost_site_merge_m`）✓ 明细见 0.4b 节。<br>**为什么是「范围+容许」而不是「离锚点 50 米」**（玩家 2026-09-29 建议）：锚点是上次按 K 时你站的位置，基地往往比它大得多 ⇒ 你站到基地另一头就被误判成「不是同一个地方」；按蓝图范围判定就都对得上（取 `max(尺寸x, 尺寸y)` 当正方体边长 ⇒ 与朝向无关） |
| `resume_save_interval_s` | `10` | 位置记忆的**落盘间隔**（秒）—— **不是每次放置都写文件**：放置/微调只改内存，攒着由定时器批量落盘；收起投影/按 `F8`/攒够 20 次改动时立刻落一次 |
| `ghost_hide_placed` | `true` | ★ **已经放上去的那一件，投影就不再画**。<br>**为什么**（实测）: 实物和投影蓝色网格**几乎完全重合**时，两个面争夺深度（z-fighting）⇒ 肉眼看到"彩色 / 蓝色交替闪"。打开后放好的那一件从投影里消失；**拆掉之后会自动恢复**（每 2.5 秒检查一次）。 |
| `ghost_hide_enum` | `true` | 允许"**枚举关卡建筑**"那条路子（= **按 `K`/`L` 放投影时扫一遍，把已经放过的件标成不显示**）。从 .9 起一直在用、只在按 K 时跑一次，实测没崩过；关掉的话"放过的件"在重放投影后会重新显示（又会闪）。<br>⚠️ 它读的 `level.Actors` **会保留已摧毁的 actor** —— 所以**不要**把它变成长时间/高频调用（那正是下面 `ghost_hide_scan` 的问题）。 |

## 6. 加新开关 / 改配置的规矩（**必须遵守**）

> 同一份规矩也写在代码里（`pwpr_config.lua` 文件头）和 `项目状态与路线图.md` 第 8 节 —— 
> 因为"配置改了但没人知道"是这类项目最容易积累的坑。

1. **改了某个键的默认值** ⇒
   * 在 `CONFIG_VERSION` 上加一版，并在 `MIGRATIONS` 里迁移
     （否则老配置文件里的旧值会**永远压住**新默认值 —— 这个坑踩过 4 次）；
   * 在键的注释和这份文档里写明"什么时候改的、为什么"。
2. **新增参数** ⇒
   * `DEFAULTS` 里加键（注释必须写"为什么需要、什么时候该改"）；
   * `Config.KEY_GROUP` 里归组（**新参数一律是 1 = 正在起作用**）；忘了不会报错，但会在配置文件里落到第 1 组；
   * 在这份文档里补一行（放在**对应文件**的**对应分组**下）。
3. **修改参数语义** ⇒ 改代码注释 + 改这份文档（含默认值与说明）。
4. **作废参数** ⇒ **不要删键**（老配置文件里还有它）：
   * 键保留、默认值留原样；
   * 在 `DEFAULTS` 注释里标 `【已不生效】/【已废弃】/【永久禁用】` 并写清原因；
   * 在 `Config.KEY_GROUP` 里归到 **3 = 历史 / 探索期遗留**；
   * 在这份文档的 **1.3 节**加一行（曾经用途 + 现在被谁取代）。
5. **正文里出现"这个功能现在没用了"时** ⇒ 在代码那处也加一行
   `【探索期遗留·…】` 注释（这样读代码的人不会以为还要维护它）。
6. 收尾跑检查器：
   ```powershell
   python tools\check_config_doc.py
   ```
   它会强制两件事：**每个 `DEFAULTS` 键都在这份文档里**、**每个配置文件都被本文档点名**；
   并且它会**扫描代码里出现的新 `.json`** —— 有新配置文件没登记就直接报错
   （防止再出现"好几个名字差不多的配置文件分不清"的情况）。
