## 0. 文件清单（先看这里，分清哪个文件是干什么的）

游戏目录下的 `<mod>` = `…\Palworld\Mods\NativeMods\UE4SS\Mods\PWBlueprint\`

| 文件 | 是什么 | 谁来改 | 部署时 |
|---|---|---|---|
| `Scripts\pwbp_config.json` | ★ **主配置**（本文档第 1 节，40+ 个开关） | **你** | 不覆盖（保留你的修改） |
| `Scripts\pwbp_meshmap.default.json` | 网格覆盖表（建筑类型 → 资产路径），随 mod 分发 | **不要改** | **会被覆盖**（更新自动生效） |
| `Scripts\pwbp_meshmap.json` | 你的网格覆盖表：补/覆盖上面那份 | **你** | 不覆盖 |
| `Scripts\pwbp_capabilities.json` | 能力探测（按 `N`）的结果缓存 | 删掉即重新探测 | 不覆盖 |
| `blueprints\index.txt` | 蓝图库索引（代码自动维护） | 不用管 | 不覆盖 |
| `blueprints\*.blueprint.json` | 蓝图数据本体（不是配置文件） | 手抄路径时可直接拷进来 | 不覆盖 |
| `Scripts\pwbp.log` | 运行日志（排查用） | 只读 | — |
| `Scripts\pwbp_meshes.txt` | 采集时导出的"网格注册表 + 类型→网格反查"报告（查缺件用） | 只读 | — |
| `Scripts\pwbp_ui.txt` | 按 `O` 生成的界面/提示探测报告 | 只读 | — |
| `Scripts\pwbp_probe.txt` | 按 `N` 生成的能力探测报告 | 只读 | — |

> 后四个**都是报告，不是配置**，随时可以删（下次操作会重新生成）。

## 1. `Scripts\pwbp_config.json` —— 主配置

### 怎么改

| 步骤 | 说明 |
|---|---|
| 1 | 打开 `<mod>\Scripts\pwbp_config.json` |
| 2 | 按下面的键名加/改一行（JSON 格式） |
| 3 | 游戏里按 **F8** 即时重载（不用重启游戏） |

**文件里的 `_readme` / `_section_1..3` 是代码写出来的分组标题**（下划线键会被忽略），
只是为了让文件自己解释自己。只有**和默认值不同**的键才会出现在文件里
（这样我们改默认值时，你的配置不会压住新默认值）。

**代码维护的键（不要手改）**：

| 键 | 含义 |
|---|---|
| `config_version` | 配置结构版本。代码升级时靠它做迁移（把老配置里的旧键补/改成新语义），**手改会导致迁移跑错** |

### 1.1 【正在使用】功能开关 —— 正常使用，别动

#### 采集（按 `Y` = 玩家附近 / 按 `U` = 全部）

| 键 | 默认 | 含义 / 什么时候改 |
|---|---|---|
| `capture_radius_m` | `150` | "玩家附近"的半径（米）。基地特别大就调大；只想采一小块就调小 |
| `capture_max` | `6000` | 单次采集上限，防止一不小心把整张地图的建筑都读进来 |
| `layer_gap_cm` | `200` | 分层阈值：相邻 Z 差超过它就认为进了新的一层（按 `L` 分层显示用） |
| `origin_snap_m` | `1.0` | 蓝图原点吸附到多少米的网格（让不同次采集的原点尽量一致） |

#### 蓝图库

| 键 | 默认 | 含义 / 什么时候改 |
|---|---|---|
| `blueprint_dir` | `""` | 蓝图存放目录。留空 = `<mod>\blueprints` |
| `blueprint_name_with_time` | `true` | 文件名是否带**易读采集时间**：`true` → `base_-1620_-609_2026-09-28_1430.blueprint.json`（每次采集都是新文件、**不覆盖**）；`false` → `base_-1620_-609.blueprint.json`（按基地名**覆盖**，只留最新一份） |

#### 投影（渲染）

| 键 | 默认 | 含义 / 什么时候改 |
|---|---|---|
| `ghost_enabled` | `false` | 投影总开关（受能力探测门禁，`N` 探测通过后才允许） |
| `ghost_max_instances` | `6000` | 超过就拒绝渲染（保护帧率） |
| `ghost_material` | `"building"` | 投影材质（游戏里 F9 进 material 模式，`←`/`→` 切；`+`/`-` 也行）。可选 `building`(蓝) / `error`(红) / `original`(原材质) 等 |
| `player_feet_offset_cm` | `0` | 玩家"脚底"相对 Actor 原点的距离（厘米）。`0` = 自动读胶囊体半高（读不到用 90）。**投影浮空/陷进地面时直接填数字微调** |

#### 交互步长

| 键 | 默认 | 含义 |
|---|---|---|
| `nudge_step_cm` | `100` | 小键盘一次挪多少厘米（`0` 键换步长档位） |
| `rotate_step_deg` | `15` | 一次转多少度 |

#### 屏幕提示（游戏内文字，详见 `docs\屏幕提示功能.md`）

| 键 | 默认 | 含义 / 什么时候改 |
|---|---|---|
| `hud_enabled` | `true` | 屏幕提示总开关（兜底通道是控制台，零风险，没有理由关） |
| `hud_seconds` | `10.0` | 提示停留几秒。**计时从"提示真正显示出来的那一刻"起算**（实现：`ExecuteInGameThreadWithDelay` 延迟回调）。⇒ **加载(`J`)/投影(`K`)在操作完成后才发提示，所以卡顿不算在内**；**采集(`Y`/`U`)的提示在"网格注册表导出"之前就发了**（导出要几秒），那几秒**算在内** |
| `notify_channel` | `"auto"` | `auto` / `console` / `game`：走哪条通道（auto = 游戏内优先，没有就控制台） |
| `notify_min_interval` | `0.25` | 节流窗口（秒）。小键盘/方向键会按键重复速率触发，不节流会刷屏 |
| `notify_autohide` | `true` | 自己的控件几秒后自动收起（秒数用 `hud_seconds`） |
| `notify_own_widget` | `true` | **自建**通知控件（Create Widget + AddToPlayerScreen），而不是往游戏现有控件里写字 |
| `notify_widget_class_name` | `"WBP_Warning_LowMemory_C"` | 复制哪个控件类当浮层（要"天生独立的浮层"，不能复制通知列表里的一项） |
| `notify_widget_text_child` | `"Text_Warning"` | 上面那个控件里显示文字的子控件名 |
| `notify_widget_class_path` | `""` | 拿不到活实例时，用这个完整路径去 `LoadAsset` 加载控件类 |
| `notify_try_notice_text` | `true` | 允许走"游戏内中文提示"路线（找到活着的 TextBlock 后 `SetText(FText("中文"))`） |
| `notify_style_retry_s` | `60` | 某个样式创建失败后，多久内不再重试（半成品控件反复创建会堆在视口里 → 后续崩溃） |

#### 启动期钩子

| 键 | 默认 | 含义 / 什么时候改 |
|---|---|---|
| `hook_load_map_pre` | `true` | 注册 **LoadMapPre** 钩子 —— 换地图时**只丢 Lua 引用**（不碰引擎），是"回标题 → 重进世界 → 闪退"的正解。**不要关** |

## 2. `Scripts\pwbp_meshmap.default.json` —— 网格覆盖表（随 mod 分发，**别改**）

作用：把**建筑类型名**映射到**静态网格资产路径**。

为什么需要：Palworld 的"类型名"和"资产名"用词不一致（地基叫 `Floor` 不叫 `Foundation`；
床只有四种 `SM_PalBed*`，而类型有 `_02/_03/_04/_06`），自动匹配不可能 100% 覆盖。

| 项 | 说明 |
|---|---|
| 值的形状 | 单网格 `"类型": "/Game/.../X.X"`；**多件拼装** `"类型": [ "…A", "…B" ]`；**不要画** `"类型": "-"` |
| `_group_*` 键 | 分组说明（会被忽略）。每组都写了"这条是怎么查出来的" |
| 改动方式 | **不要直接改这个文件**（部署时会被覆盖）⇒ 改第 3 节那个用户表 |
| 校验 | `python tools\check_meshmap.py mod\PWBlueprint\Scripts`（含重复键、多网格、路径合法性） |

## 3. `Scripts\pwbp_meshmap.json` —— 你的覆盖表（部署**不覆盖**）

| 项 | 说明 |
|---|---|
| 优先级 | 先读 `default`，再读这个 ⇒ **同名键以你为准** |
| 什么时候用 | ① 某个建筑画不出来 / 画得不对；② 想让它"不画"（写 `"-"`） |
| 怎么找正确路径 | 采集后看 `pwbp_meshes.txt`（里面有"从网格组件反查【建筑类型 → 网格】"一节，**照着抄**即可） |
| 生效方式 | 保存后按 `F8` |

## 4. `Scripts\pwbp_capabilities.json` —— 能力探测缓存

| 项 | 说明 |
|---|---|
| 谁写的 | 按 `N`（能力探测）后自动写入；`ghost_enabled` 的门禁就是看它 |
| 什么时候删 | 换了游戏版本 / UE4SS 版本后想**重新探测**就删掉它 |
| 内容 | 每项能力的探测结果（可用/不可用/用了哪种调用写法），不是给人手改的 |

## 5. `blueprints\index.txt` 与 `blueprints\*.blueprint.json`

| 文件 | 说明 |
|---|---|
| `index.txt` | 蓝图库索引，代码自动维护（`J` 切下一张时按它走）。**不用手改** |
| `*.blueprint.json` | 蓝图本体，格式见 `docs\蓝图格式.md`。可以手动拷进来（放进目录后按 `F8` 刷新） |

## 6. 加新开关 / 改配置的规矩（**必须遵守**）

> 同一份规矩也写在代码里（`pwbp_config.lua` 文件头）和 `项目状态与路线图.md` 第 8 节 —— 
> 因为"配置改了但没人知道"是这类项目最容易积累的坑。

1. **改了某个键的默认值** ⇒
   * 在 `CONFIG_VERSION` 上加一版，并在 `MIGRATIONS` 里迁移
     （否则老配置文件里的旧值会**永远压住**新默认值 —— 这个坑踩过 4 次）；
   * 在键的注释和这份文档里写明"什么时候改的、为什么"。
2. **新增参数** ⇒
   * `DEFAULTS` 里加键（注释必须写"为什么需要、什么时候该改"）；
   * `Config.KEY_GROUP` 里归组（**新参数一律是 1 = 正在起作用**）；忘了不会报错，但会在配置文件里落到第 1 组；
   * 在这份文档里补一行（放在**对应文件**的**对应分组**下）。
3. **修改参数语义** ⇒ 改代码注释 + 改这份文档（含默认值与说明）。
4. **作废参数** ⇒ **不要删键**（老配置文件里还有它）：
   * 键保留、默认值留原样；
   * 在 `DEFAULTS` 注释里标 `【已不生效】/【已废弃】/【永久禁用】` 并写清原因；
   * 在 `Config.KEY_GROUP` 里归到 **3 = 历史 / 探索期遗留**；
   * 在这份文档的 **1.3 节**加一行（曾经用途 + 现在被谁取代）。
5. **正文里出现"这个功能现在没用了"时** ⇒ 在代码那处也加一行
   `【探索期遗留·…】` 注释（这样读代码的人不会以为还要维护它）。
6. 收尾跑检查器：
   ```powershell
   python tools\check_config_doc.py
   ```
   它会强制两件事：**每个 `DEFAULTS` 键都在这份文档里**、**每个配置文件都被本文档点名**；
   并且它会**扫描代码里出现的新 `.json`** —— 有新配置文件没登记就直接报错
   （防止再出现"好几个名字差不多的配置文件分不清"的情况）。
