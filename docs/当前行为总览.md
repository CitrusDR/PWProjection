## 1. 它是什么 / 做到哪了

把基地**采集**成蓝图（`*.blueprint.json`），然后在任意位置以**半透明幽灵**投影出来，
一层一层看、随手挪、**放下的建筑自动从投影里消失**（避免"蓝色投影 + 彩色实物"重叠闪烁）。

**已完成并实机验证**:

| 功能 | 状态 |
|---|---|
| 采集（范围 / 全部）→ 蓝图文件 | ✓ 可用 |
| 投影（幽灵、材质、分层、骨骼网格、微调、旋转） | ✓ 可用 |
| **建造吸附**（放下建筑时自动吸到投影对应位置） | ✓ 可用（`buildsnap_*` 参数可调） |
| **已放上的不再投影**（3 秒批量结算） | ✓ 可用 |
| **位置 / 进度记忆**（多处记录、`U` 切换、跨存档沿用） | ✓ 可用 |
| **拆掉自动恢复**（扫描只减不增） | ✓ 可用（按 `K` 时核对） |
| 屏幕提示 | ✓ 可用（按 `O` 探测通道） |

## 3. 「已放上」名单（哪些件不再画）—— 只有两个来源

1. **精确通道**：建造吸附在改写放置请求时**明确知道**"我正要往第几条记录放"
   ⇒ 直接登记（不需要猜）✓
2. **记录里存的进度**：`pwpr_placements.json` 里每一处的 `placed` 列表 ✓

**扫描（枚举关卡建筑）只做一件事：只减不增** ——
名单里的每一条，用它在该锚点下的**世界坐标**去找附近（默认 40 厘米，`ghost_hide_placed_cm`）
有没有真实建筑：**在 ⇒ 继续不画；不在 ⇒ 恢复渲染**（拆掉自动恢复）。
**扫描绝不往名单里加**（原因见 `踩坑记录.md` 的"扫描认领是歧义的"一条）。

**3 秒批量窗口**：连放时先入队，安静 3 秒（`ghost_hide_placed_batch_s`）后一起结算，
只重灌受影响的组件（不重灌整个投影）。

## 4. 位置 / 进度记忆 —— 两个半径，各管各的

（详细表格见 `docs\配置说明.md` 第 0.4b 节）

| 用途 | 半径 | 为什么 |
|---|---|---|
| **`K` 沿用** | **蓝图包围盒一半 + `ghost_resume_margin_m`**（这张蓝图 ≈ 53 米，宽）| `K` = "对齐到这个世界"：站在基地任何角落按 `K` 都该认出"我在哪一处"，沿用它的位置 + 朝向 + 偏移 + 进度 |
| **登记 / 写回进度** | **`ghost_site_merge_m`**（默认 **10 米**，紧）| 只有"就在这一处旁边"才算同一处 ⇒ 换个地方建 = **新的一处** ✓ |
| **`H`** | **完全不查** | 放脚下 + 名单清空 + 完整重灌 ⇒ 一份完整的新投影 ✓ |
| **`U`** | 不看距离 | 按创建顺序切记录 ✓ |

* 判定比的是**水平距离**（**忽略高度 z**）—— 同 x/y 不同高度算同一处（取舍见 §6）
* **记录只由"真放过建筑"产生**（`bind_progress`）；只挪投影不会新增记录 ✓
* `K` / `H` / `U` 都会**完整重灌**（`refresh_projection(..., rebuild = true)`）——
  只搬变换的"省事路径"会让上一处的隐藏状态残留 ✗（踩过，见 `踩坑记录.md`）

## 5. 数据与落盘

| 文件（在 `...\Mods\PWProjection\Scripts\`）| 内容 |
|---|---|
| `pwpr_placements.json` | 位置 / 进度记忆: `placements[蓝图文件名].sites[]`，每条含锚点 x/y/z、朝向、偏移、蓝图尺寸、`placed`（已建记录序号）|
| `pwpr_config.json` | 只写"和默认值不同"的键；`F8` 即时生效；`config_version` 用于默认值迁移 |
| `pwpr.log` | 运行日志（关键行: `构建标记` / `[bsnap]` / `[placed]` / `[resume]` / `[diag]`）|

* **落盘是批量的**: 内存记账，每 `resume_save_interval_s`（10 秒）/ 收起投影 / 攒够 20 次改动写一次
  —— **不是每次放置都写文件** ✓
* 清理记录:
  `python tools\resume_tool.py --file "<...>\pwpr_placements.json" list|drop-site|drop-progress|drop-blueprint|drop-all`
  （**先关游戏**）

## 6. 已知取舍 / 限制（重要）

| 取舍 | 说明 |
|---|---|
| **`H` 那一份不跑扫描** | 所以 `H` 之后**拆掉**某件，投影不会自动恢复 ⇒ 按一次 `K` 让它重新核对世界 |
| **非本模组放的老建筑不会自动识别** | 扫描只减不增 ⇒ "旧基地继续建"要按 `K`，用吸附逐件放（精确通道会登记）|
| **判定忽略高度** | 同 x/y 不同高度（楼上 / 地道）算同一处；想区分就把两个半径都调小 |
| **`level.Actors` 会保留已摧毁的 actor** | 所以"查引用还在不在"的快路径默认关闭（`ghost_hide_alive_check`），拆掉恢复靠全扫 |
| **少部分建筑画不出来** | 见 `mod\PWProjection\已知限制.md`（缺网格 / 骨骼映射）|
| **原生崩溃不可归因到单次 Lua 调用** | 所以关键路径都有日志点与开关 ✓ |

## 7. 排查顺序（踩坑后总结，按这个顺序最快）

1. **部署成功了吗** —— 看 `deploy.ps1` 的**输出**（现在会先跑静态检查，通过才复制）；
   `.ps1` 自己有语法错误时**一行都不会执行** ✗
2. **游戏里跑的是哪一版** —— `pwpr.log` 第一行「构建标记」对不对 ✓
3. **功能读到数据了吗** —— `[resume]` 行（沿用 / 没有记录 / 换算）、`投影位置记忆: 已记 N 张蓝图` ✓
4. **名单是对的吗** —— `[diag] apply_placed_mask: 名单 N 件`、`[placed] 只减不增: …`、
   `[placed] 增量重灌: … 跳过 N 件` ✓
5. 然后才是逻辑推理 ✓

> 2026-09-29 这一晚，几乎每一个"功能突然不生效"最后都落在第 1~4 步里，而不是算法本身 ——
> 具体案例见 `docs\踩坑记录.md` 顶部的「因果链总览」。
