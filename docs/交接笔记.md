2. **静默失效最危险** —— 每一次这种修复都要配一条**覆盖率自检**（例：采集后打印"有网格 N / 有完整路径 M"）；
3. **不可靠的信号连"跳过"都不能做** —— 会让功能静默坏掉，而且看起来像"功能本身有问题"（§25）。

**已知限制（跟玩家怎么说）**：
* 伐木场/采石场这类**多件拼装**建筑目前只画**主件近似**（"一棵树 + 几块石头"），完整拼装要等**待办 3**；
* 金属采矿场2 与采石场**共用同一套外观资产**，看起来像**不是 bug**；
* 用**旧蓝图**（没有 `mesh_path` 字段）跨存档投影仍可能缺件 ⇒ **回源存档重采一次**。

### ★ 用真实数据验证过的一件事：分层会分成什么样

拿主基地 358 件的真实坐标算了一遍（`out/real-near300.blueprint.json`）：

| Z 值 | 件数 | 是什么 |
|---|---|---|
| -1.17 ~ -1.15 | **349** | 地基 + **墙** + 设施 + 床 |

## 七、工作约定（重要，别忘）

### 🔴 硬性规矩：改动 main.lua 后必须跑 luacheck

2026-09-26 发生过一次**真实游戏崩溃**：一次"去重"编辑误删了 `playerPawn` 函数定义，
但调用处还在 → Lua 报 `attempt to call a nil value` → 游戏崩
（`EXCEPTION_ACCESS_VIOLATION`）。详见 `踩坑记录.md` **3f-9 节**。

当时的"校验"（括号配平 + 手写关键函数清单）**都没拦住**——
手写清单偏偏漏了那个函数。

**所以现在有 `tools/luacheck.py`**（静态提取所有被调用标识符反查定义）：

```powershell
$py = "C:\Users\<用户名>\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
& $py tools\luacheck.py mod\PWRecon\Scripts\main.lua
# 必须输出「结果: 无严重问题」才能部署
```

它会抓：**未定义的被调用标识符** / 括号配平 / 重名函数 / 危险 pcall 写法 / print 里的中文。

### 🔴 侦察脚本必须遵守"只读原则"

今天因为"运行时调用引擎函数"崩了不止一次。区分：

| 操作 | 风险 |
|---|---|
| 读属性 / 读方法引用 | ✅ 安全 |
| 读已知安全的 getter（`K2_GetActorLocation` 等） | ✅ 安全 |
| **调用**未验证的引擎函数（spawn / `AddInstance` / `StaticFindObject`） | 🔴 **可能崩** |
| **调用**会改世界状态的方法（`SetMaterial` / `SetActorTransform`） | 🔴 崩 + 污染世界 |

1. 只读属性和方法引用，**不调用**改状态的方法
2. 调引擎函数一律 `pcall(function() ... end)` **闭包包裹**，
   **绝不** `pcall(StaticFindObject, "arg")`（实测会崩）
3. 想验证"能不能调用"，先只探测方法引用**是否存在**（读属性安全），
   真正调用留到有回滚手段的单独一轮

### 🚑 崩了之后怎么快速禁用 mod

不需要进游戏，改 `mods.txt` 即可：

```
D:\Steam\steamapps\common\Palworld\Mods\NativeMods\UE4SS\Mods\mods.txt
把 "PWRecon : 1" 改成 "PWRecon : 0"
```

或改名目录：`...\UE4SS\Mods\PWRecon` → `PWRecon.off`
