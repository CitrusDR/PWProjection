## ★★ 已确认的关键技术事实（都是实测，别重新试错）

### 建筑数据怎么拿

```lua
FindAllOf("PalBuildObject")            -- 所有建筑（某存档 649 个 / 79 种类型）
obj:GetClass():GetFullName()           -- 类型: BP_BuildObject_Wood_Foundation_C → Wood_Foundation
obj:K2_GetActorLocation()              -- 世界坐标，读 .X/.Y/.Z
obj:K2_GetActorRotation()              -- 朝向，读 .Yaw
obj.Mesh  →  .StaticMesh               -- 网格资产（属性名是 Mesh，不是 StaticMesh！）
obj.MapObjectModel                     -- 关联对象
FindAllOf("PalMapObjectManager")       -- 管理器（单例）
```

### ❌ 这些看起来该能用，实际不能（省下你踩坑的时间）

| 写法 | 实际情况 |
|---|---|
| `ForEachUObject(cb)` | **不可用**！返回的是 UE4SS 的 Lua 包装对象名（`FNameUserdata:<地址>`），不是 UObject 类名。遍历 41 万对象产出 29 万行垃圾 |
| `obj:GetActorLocation()` / `GetActorRotation()` / `GetActorTransform()` | 未绑定，调用返回 `TrivialObject`。**只有 `K2_` 前缀版本被绑定** |
| `obj.Transform` / `obj.Location` / `obj.Rotation` | 全是占位对象。UE 里 Actor 位置在 `RootComponent.ComponentToWorld` |
| `obj:ForEachProperty()` / `obj:GetComponents()` | 未绑定 |
| `obj.StaticMeshComponent` | 占位对象 |
| 读取不存在的属性 | **不报错也不返回 nil**，而是返回占位对象 → **不能靠"读取成功"判断字段是否存在** |
| `#v` 判断空值 | `K2_GetActorLocation()` 返回 **keyed table 不是数组**，`#v` 得 0 但它不是空值 → 直接试读 `.X` |
| `RegisterKeyBind("F7", fn)` | **字符串键名不行**。必须 `RegisterKeyBindAsync(Key.F7, {}, fn)` |
| `IsKeyBindRegistered` | 结果不可靠（实测与真实注册状态不符），**不能用它判断注册成功** |
| 解析 1.0 存档 | 是 `PlM1`（**Oodle 压缩**）且地图对象换了新格式，**这条路已放弃** |

**发现新类名的正确方法**：`FindAllOf` + 候选名单**逐个精确试**（每次毫秒级）。
**不要**用全量枚举。已确认存在的类见 `踩坑记录.md` 3c 节。

### 输出编码（两个坑）

- **日志**：UE4SS 的 `print()` 按系统 **ANSI(GBK)** 写日志 → 中文乱码。
  **控制台只输出 ASCII，完整中文写文件**
- **文件**：`io.open(path, "wb")` + 手动写 UTF-8 BOM（`"\239\187\191"`），否则中文乱码

## ★ 下一步要做什么（阶段 2：渲染原型）

### 第一步：侦察游戏自带的半透明机制（**优先做这个，成本低**）

**用户实测观察**：

| 状态 | 颜色 |
|---|---|
| 允许放置 | **浅蓝色**半透明 |
| 不允许放置（位置冲突） | **浅红色**半透明 |
| 已放置但**建造中**的建筑 | 也是**半透明** |

**这说明游戏内已有完整的"半透明建筑渲染"实现**，包括"可放/不可放"着色。
**优先找到并复用，不要自己造材质。**

侦察方向：

```lua
FindFirstOf("PalBuildObjectGhost")        -- 类名待验证
FindFirstOf("BP_PalBuildObjectGhost_C")
FindFirstOf("PalBuildSystem")
```

辅助工具：UE4SS 自带 `Mods/ConsoleCommandsMod/Scripts/dump_object.lua`
可以 dump 单个对象的属性。注意 `ConsoleCommandsMod` 在 `mods.txt` 里是禁用的。

### 第二步：渲染原型（真正的硬骨头）

- 硬编码或从蓝图读几十件建筑，画在玩家面前
- **必须避免**：不要为每件建筑 `SpawnActor`（649 件 = 649 个 Actor，
  带 Tick/碰撞/网络复制/GC，帧率会崩）
- **正确做法**：按类型分组，同类实例放进同一个 **ISM/HISM + 半透明材质**
- 分层展示：用 per-instance custom data 控制 alpha 衰减，避免重建实例

### 并行可做（用户侧，简单）：继续积累 `type → mesh` 映射表

实测发现**同一类型的不同实例，`Mesh` 可读性不一致**
（`MedicalPalBed_02` 在主基地能读到，在第二据点读不到）。
已做"按类型聚合"修正，但数据不全（3/11、26/79）。

**让用户换据点重复**：进游戏 → 按 `Y`（设中心）→ `K`/`L`（调半径）→ `J`（导出）
→ 把 `buildings_raw.tsv` 发回来。

> ⚠️ **结构件（墙/地板/屋顶）永远没有 mesh** —— 大概率是 ISM 批量渲染，
> 需要另找资产来源。**别期待能到 79/79。**

## 工作约定（重要）

1. **AI 不能写游戏目录**：DSH 文件沙箱只允许写 `D:\dsh-workspace`。
   所有产出放工作区，**用户手动部署**。
   → 涉及游戏目录的操作，生成脚本让用户跑，不要尝试自己写。
2. **改 `.ps1` 后必须**：补 UTF-8 BOM（PS 5.1 无 BOM 会按 GBK 读，中文乱码）
   + 静态语法检查。注意 `->` 在字符串里会破坏解析、单引号里不能嵌双引号
3. **改 `.lua` 后必须做括号配平检查**（AI 无法执行 Lua，只能静态验证）。
   注意：`ForEachProperty` 里的中文注释不影响解析，但**诊断代码用 `Get-Content`
   读文件会按 GBK 读导致假错误**，要用 `[System.IO.File]::ReadAllText()`
4. **每个"实测确认"的结论都要写进 `docs/踩坑记录.md`** —— 这是防上下文丢失的核心
5. **出问题先取证（看日志、看文件），再推理。**
   前一会话有三次因为跳过取证直接推理而误判，浪费了大量时间
