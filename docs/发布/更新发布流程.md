# 更新发布流程（Steam 创意工坊 + Nexus Mods）

> 2026-10-08 定稿。以后每次改完代码照这份走。
> **核心提醒：两个平台的描述语法完全不同，文案不能互抄**（见第 1 节）。

## 1. 🔴 描述语法差异（最容易出事的地方）

| | Steam 创意工坊 | Nexus Mods |
|---|---|---|
| **格式** | **BBCode** | **Markdown**（富文本编辑器）|
| 粗体 | `[b]文字[/b]` | `**文字**` |
| 标题 | `[h2]标题[/h2]` | `## 标题` / `### 标题` |
| 列表 | `[list][*]项[/list]` | `- 项`（有序 `1.`）|
| 代码/路径 | `[code]路径[/code]` | ⚠️ **不要用反引号** —— 会被渲染成独立灰框，把句子切碎 ✗ |
| 链接 | `[url=https://…]文字[/url]` | `[文字](https://…)` |
| 分隔线 | `[line]` | `---` |
| 文案文件 | `页面文案.md` 的**工坊段** | **`N网描述_粘贴版_v2.md`**（英文 + 中文合一）|

**实测两个坑（都踩过）：**
1. 把 BBCode 粘进 N 网 ⇒ `[list]` `[b]` `[size=4]` `[code]` **原样显示**，页面很乱；
   而且 N 网向导会把 `[code]` 块抠成一个个独立输入框 ✗
2. N 网里**行内反引号**会变成块级灰框（"（里面要有" 和 "）。" 被拆到两个框）✗
3. 工坊那边反过来：**Markdown 语法在 BBCode 里不生效**（`###` 就是三个井号）✗

## 2. 一次更新的完整流程

```powershell
# ① 改代码 → 跑检查器（规矩 3）
python tools\luacheck.py mod\PWProjection\Scripts      # 必须 24 文件 0 问题
python tools\selftest.py ; python tools\buildsnap_sim.py ; python tools\snap_sim.py
python tools\resume_sim.py ; python tools\check_keys.py ; python tools\check_config_doc.py
python tools\check_bom.py ; python tools\_linkcheck.py
powershell -NoProfile -ExecutionPolicy Bypass -File tools\check_ps_syntax.ps1
```
```
# ② 改版本号（两处都要）
mod\PWProjection\workshop\Info.json   →  "Version": "x.y.z"
（内部构建标记 Util.BUILD 由我改；日志第一行会打出来）

# ③ 更新更新日志（会打进 N 网 zip 的 CHANGELOG.md）
docs\发布\更新日志.md   →  在最上面加一节 "## x.y.z —— …"

# ④ 打包（-Force = 覆盖同名版本重打）
powershell -NoProfile -ExecutionPolicy Bypass -File D:\dsh-workspace\palworld-litematica\tools\make_release.ps1
#   产出： backups\PWProjection\发布\<版本>\workshop_package\   （传工坊）
#          backups\PWProjection\发布\<版本>\PWProjection-<版本>.zip（传 N 网）
```

### ⑤ Steam 创意工坊
1. 打开 **Palworld Mod Uploader** → 选已有条目
2. 把 `workshop_package\` 的内容（`Info.json` + `thumbnail.*` + `Scripts\`）放进工坊目录
3. `Save Info.json` → **`Upload To Steam`** → 填 **Change Notes**
   （页面正文一般不用重填；要改就按 `页面文案.md` 的 BBCode 段）
4. 上传后去页面确认 **Required Items** 里还有 UE4SS（`Info.json` 的依赖不会自动同步）

### ⑥ Nexus Mods
1. 打开 mod 页面 → **`Manage files`** → **`Upload new version`**
2. 选新的 zip（**不要**用嵌套压缩包；我们的是扁平的 ✓）
3. 填版本号 + changelog（从 `docs\发布\更新日志.md` 那节抄）
4. 勾 **`Archive existing file`**（旧版本归档，页面不用重建）
5. 等 **Virus scan** 变绿（`Safe to use`）
6. 若描述内容有变 → 按第 1 节的 Markdown 规则改（**别用反引号**）

### ⑦ 两边都要做的事
- 版本号一致（工坊 `Info.json` 与 N 网文件名/版本栏）
- 更新日志一致（工坊 Change Notes = N 网 changelog = `更新日志.md`）
- `Options → Mod Management` 里确认新版本能加载（工坊更新后订阅端会自动重装）

## 3. 两份页面文案的内容对齐清单（2026-10-08 对比结果）

| 段落 | 工坊版 | N 网版 | 要补的 |
|---|---|---|---|
| 简介 / What it does | ✓ | ✓（Features）| — |
| 功能列表 | ✓ | ✓ | — |
| 前置要求 / Requirements | ✓（Required·Install）| ✓ | — |
| 安装步骤 | ✓ | ✓ | — |
| 按键 | ✓ | ✓ | — |
| **设计上的已知限制** | ✓（Known limitations: 预览不跟随 / 拆掉不自动恢复 / 拼装建筑只画主件 / blueprint 模式未完成 / 联机未验证）| ✗ **缺** | **N 网补一段** |
| **常见问题排查** | ✓（Troubleshooting）| ✗ **缺** | **N 网补一段** |

| 致谢 Credits | ✓ | ✓ | — |

## 4. 版本号规则

- **模组版本**（玩家可见，如 `1.0.5`）：`Info.json` 的 `Version`，N 网文件版本栏；
  工坊靠它判断"有更新"⇒ **每次更新必须改**（只换缩略图不用改）。
- **内部构建标记**（`Util.BUILD`，如 `2026-10-09.119`）：日志第一行会打；
  排查时**先确认这一行**，对不上说明跑的是旧版。
