# 修复：UE4SS 没加载，所以 F7/F8/F9/F6 全都没反应

## 结论先说

**这不是侦察脚本的问题。你的 UE4SS 根本没有被注入到游戏里**，所以任何 Lua mod
（包括原来能用的 FirstPerson 的 F6）都不会有反应。

证据（全部来自实际探测，不是推测）：

| 检查项 | 实测结果 | 含义 |
|---|---|---|
| `Win64` 目录里的注入代理 `dwmapi.dll` | **不存在** | 没有任何东西把 UE4SS 挂进游戏进程 |
| `UE4SS.log` 最后写入时间 | **2026-08-08 22:40**（停更 48 天） | UE4SS 从那天起就没启动过 |
| `PalModSettings.ini` 的 `ActiveModList` | **空的** | 官方 mod 系统没启用任何 mod |
| 本地 UE4SS.dll | 16.5MB，2026-08-08，`experimental-palworld-5` | 是旧且残缺的版本 |
| 创意工坊 UE4SS.dll | 20.0MB，2026-09-05，`2281fa31` | 已有更新版，但没部署到本地 |
| 本地缺 `UE4SS_SDK_Backends` | **缺失** | 官方部署记录里本来就没有它，属正常 |
| 游戏本体更新时间 | **2026-09-15** | 游戏更新过两次，UE4SS 没跟上 |

UA4SS 官方 release 页面明确点名了两个坑，你两个都踩了：

> "This fixes crashing issues related to **FText** from the old version."
> —— 旧版有 FText 崩溃 bug（你那个 0 字节的 `crash_2026_08_08_22_58_35.dmp` 就是）

> "if you're using the workshop version of UE4SS, you should NOT have this installed
> at the same time, otherwise the game **WILL** crash due to attempting to load
> two copies of ue4ss at the same time."
> —— 本地版和创意工坊版不能并存

**时间线还原**：

```
2026-07-19  创意工坊 UE4SS 更新到该版本
2026-08-08  官方 mod 系统部署到本地 → UE4SS 正常工作，F6 可用  ← 日志停在这一天
2026-08-08 22:58  UE4SS 崩溃（0 字节 dmp）
2026-09-05  创意工坊 UE4SS 更新到 2281fa31（但没同步到本地）
2026-09-15  游戏本体更新
2026-09-26  你安装 PWRecon、启动游戏 → UE4SS 没加载 → 所有热键失效
```

---

## 修复方案

### 方案 A（优先，不需要下载任何东西）

**第 1 步：完全退出游戏**

任务管理器确认没有 `Palworld-Win64-Shipping.exe` 进程。

**第 2 步：在游戏内重新启用 UE4SS**

这是关键。`ActiveModList` 为空，说明官方 mod 菜单里的开关是关的。

1. 启动游戏（**直接从 Steam 启动**，不要通过 mod 管理器）
2. 在主菜单找 **设置 / Settings** 里的 **mod / 模组 / MOD 管理**
   （Palworld 1.0 新增的官方 mod 菜单）
3. 把 **`UE4SS Experimental (Palworld)`** 打开
4. 顺便把 **`True First Person MOD`** 也打开（你之前用过的）

启用后，官方 mod 系统会：
- 从创意工坊把**最新版**（2281fa31）重新部署到 `Mods\NativeMods\UE4SS`
- 安装注入代理，让 UE4SS 真正挂进游戏

**第 3 步：验证**

进游戏后按 F7。

然后**重新跑一次诊断脚本**确认（这一步很重要，别跳）：

```powershell
powershell -ExecutionPolicy Bypass -File "D:\dsh-workspace\palworld-litematica\diag\diag-ue4ss.ps1"
```

**修复成功的判据**（三条都要满足）：

```
1. UE4SS.log 的修改时间是"刚刚"
2. 诊断第 2 节：Win64 里有 dwmapi.dll
3. 诊断第 7 节：日志里出现 PWRecon
```

---

### 方案 B（方案 A 无效时的兜底：手动注入）

如果方案 A 之后 `dwmapi.dll` 还是不存在，说明官方 mod 系统的自动部署没生效，
那就手动装。

**第 1 步：下载 UE4SS（注意要 Palworld 专用版）**

打开 https://github.com/Okaetsu/RE-UE4SS/releases/latest

下载 **`UE4SS-Palworld.zip`**（约 8.6MB，不要下 `_zDev` 那个，那是给开发者编 mod 用的）

> ⚠️ 必须是 `Okaetsu/RE-UE4SS`，**不是** `UE4SS-RE/RE-UE4SS`。
> Palworld 因为 0.4.1.5 引入了引擎改动，需要专门的编译版本。

**第 2 步：解压后，把内容覆盖到**

```
D:\Steam\steamapps\common\Palworld\Mods\NativeMods\UE4SS\
```

**第 3 步：确认注入代理到位**

解压包里应该有 `dwmapi.dll`。把它复制到：

```
D:\Steam\steamapps\common\Palworld\Pal\Binaries\Win64\dwmapi.dll
```

**第 4 步：确保没有重复加载**

官方明确警告不能有两份 UE4SS 同时存在。如果你是从 Steam 创意工坊订阅的，
就不要同时放手动版；反之亦然。同时存在**必定崩溃**。

---

## 修复后要重新做的事

UE4SS 一旦重新部署，**会把 `Mods\NativeMods\UE4SS\Mods\` 目录覆盖掉**，
所以 PWRecon 需要重装：

```powershell
cd "D:\dsh-workspace\palworld-litematica\mod\PWRecon"
powershell -ExecutionPolicy Bypass -File install.ps1
```

> 注意顺序：**先修好 UE4SS，确认 F6（FirstPerson）能用了，再装 PWRecon。**
> 否则你分不清是 UE4SS 没起来还是脚本有问题。

顺便把热键重载打开（改 Lua 后不用重启游戏）：

```
D:\Steam\steamapps\common\Palworld\Mods\NativeMods\UE4SS\UE4SS-settings.ini
    EnableHotReloadSystem = 1
```

## 为什么这件事对项目很重要（不只是"环境没配好"）

这次的失败暴露了一个项目级风险，值得记下来：

**UE4SS + Palworld 的版本耦合非常紧，而游戏更新频繁。**
从 8 月 8 日到 9 月 15 日，游戏更新了两次，UE4SS 就彻底失效了。

这意味着：

1. **项目的维护成本主要不在写功能，而在跟版本。** 你的投影模组以后每次游戏大更新
   都可能需要适配。这也是那个 Nexus Mod（Simple Building Blueprints）迭代到 0.16.1
   的原因——它的大量版本都是在修"游戏更新导致失效"。
2. **开发环境要能快速重建。** 建议把"环境自检"固化下来，就是我写的 `diag-ue4ss.ps1`。
   每次开工前跑一遍，5 秒确认环境健康，比出了问题再排查省事得多。
3. **这也是我不建议一开始就上 C++ 的原因。** Lua 层面至少还能改脚本适配；
   如果是 C++ DLL mod，UE4SS 一升级，作者都得重新编译（release 说明里也提到了
   "Your .dll mods will likely crash in the beginning, but that can be solved by
   the authors updating their .dll mods to use this version of UE4SS"）。
