## 为什么可信：与"游戏里正在跑的那份"逐字节核对过

打包脚本（`tools\make_snapshot.ps1`）会自动比对
**工作区源码** vs **游戏目录 `Mods\PWBlueprint\Scripts`**：

```
[OK] 部署过去的源码与游戏目录逐字节一致（备份的就是实测通过的那一版）
[i] 用户文件与游戏里那份不同（正常，部署不覆盖它）: Scripts\pwbp_meshmap.json
```

* 比对的集合 = 部署脚本真正会复制的那些（`Scripts\*.lua` + `pwbp_meshmap.default.json`）；
* `pwbp_meshmap.json` 是**用户自己的**覆盖表，部署时故意不覆盖 ⇒ 两边不同是**预期**的；
* mod 根下的 `README.md` / `deploy.ps1` / `已知限制.md` 本来就不进游戏目录。

## 这一版包含的关键修复（详见 `docs\踩坑记录.md` §25–§31）

| 现象 | 修复 |
|---|---|
| 回标题 → 重进世界 → 闪退 | LoadMapPre 钩子只丢 Lua 引用（不碰引擎） |
| 换存档 / 换会话后投影缺件 | 蓝图写入 `mesh_path`（完整资产路径），投影端直接 `LoadAsset` |
| 高科技建筑堆在帕鲁终端上面 | 骨骼网格判定：`SK_` 名字约定兜底 + 以资产自身的类为准 |
| 老存档按 `Y` 崩在扫描中 | 改用当前关卡的 Actor 列表（不再遍历全局对象表） |
| 造组件即崩（偶发） | 组件类名黑名单（排除植被/地形等专用变体） |
| 材质只能单向切 / 采集提示被卡顿吞掉 | 方向参数 + 导出后重新计时 |

## 已知限制（这一版仍然存在，说给玩家的话术）

* **多件拼装建筑只画主件近似**：伐木场（一棵树）、采石场（几块石头）、简约门（门框）等
  —— 完整拼装要等"组件的相对变换"（路线图待办 3）；
* **金属采矿场2 与采石场共用同一套外观资产**（`StonePitLarge`），看起来像**不是 bug**；
* **旧蓝图**（没有 `mesh_path` 字段）跨存档投影仍可能缺件 ⇒ **回源存档重采一次**；
* 换存档/换会话后**第一次**加载旧蓝图时，若某个骨骼资产尚未加载，会按名字约定兜底
  （日志里会有 `注意: 分组当成静态了，但资产是骨骼网格` 一行，属正常兜底）。

## 怎么用这份快照

```powershell
# 1) 解压（任选目录），把 mod 部署进游戏
powershell -NoProfile -ExecutionPolicy Bypass -File .\mod\PWBlueprint\deploy.ps1

# 2) 校验完整性（可选，对照 校验清单.txt 里的 SHA256）
```

> 恢复旧版时注意：**不要**用快照里的 `pwbp_meshmap.json` 覆盖你游戏里那份用户覆盖表
> （如果你在游戏里补过条目的话）。
