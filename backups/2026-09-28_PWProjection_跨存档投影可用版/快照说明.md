## 为什么可信：与"游戏里正在跑的那份"逐字节核对过

`tools\make_snapshot.ps1` 自动比对**工作区源码** vs **游戏目录 `Mods\PWProjection\Scripts`**：

```
[OK] 部署过去的源码与游戏目录逐字节一致（备份的就是实测通过的那一版）
```

比对集合 = 部署脚本真正会复制的那些（`Scripts\*.lua` + `pwpr_meshmap.default.json`）；
`pwpr_meshmap.json` 是**用户自己的**覆盖表，部署时故意不覆盖 ⇒ 允许两边不同。

## 这一版包含的关键修复（详见 `docs\踩坑记录.md` §25–§33）

| 现象 | 修复 |
|---|---|
| 回标题 → 重进世界 → 闪退 | LoadMapPre 钩子只丢 Lua 引用（不碰引擎） |
| 换存档 / 换会话后投影缺件 | 蓝图写入 `mesh_path`（完整资产路径），投影端直接 `LoadAsset` |
| 高科技建筑堆在帕鲁终端上面 | 骨骼网格判定：`SK_` 名字约定兜底 + 以资产自身的类为准 |
| 老存档按 `Y` 崩在扫描中 | 改用当前关卡的 Actor 列表（不再遍历全局对象表） |
| 造组件即崩（偶发） | 组件类名黑名单（排除植被/地形等专用变体） |
| 材质只能单向切 / 采集提示被卡顿吞掉 | 方向参数 + 导出后重新计时 |
| 提示语让玩家改一个**文件里不存在**的键 | 能力探测通过后**自动**开启 `ghost_enabled`（写进配置） |

**改名**：mod 目录 / Lua 前缀（`pwpr_`）/ 日志标签（`[PWPR]`）/ 配置与数据文件名全部换成新名。
从旧版迁移的步骤见 `docs\项目状态与路线图.md` 第 10 节。

## 已知限制（说给玩家的话术）

* **多件拼装建筑只画主件近似**：伐木场（一棵树）、采石场（几块石头）、简约门（门框）等
  —— 完整拼装要等"组件的相对变换"（路线图待办 3）；
* **金属采矿场2 与采石场共用同一套外观资产**（`StonePitLarge`），看起来像**不是 bug**；
* **旧蓝图**（没有 `mesh_path` 字段）跨存档投影仍可能缺件 ⇒ **回源存档重采一次**；
* 换存档/换会话后**第一次**加载旧蓝图时，若某个骨骼资产尚未加载，会按名字约定兜底
  （日志里会出现 `注意: 分组当成静态了，但资产是骨骼网格` 一行，属正常兜底）。

## 怎么用这份快照

```powershell
# 1) 解压，部署进游戏（脚本会注册 mods.txt，并停用改名前留下的旧条目）
powershell -NoProfile -ExecutionPolicy Bypass -File .\mod\PWProjection\deploy.ps1

# 2) 首次进游戏: 按 N 做一次能力探测（通过后自动开启投影开关）→ 按 K 放投影

# 3) 可选: 用 校验清单.txt 里的 SHA256 核对完整性
```

> 不要用快照里的 `pwpr_meshmap.json` 覆盖你游戏里那份**用户覆盖表**（如果你补过条目）。
