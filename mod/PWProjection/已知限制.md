# PWProjection —— 已知不支持 / 已知限制

> **这份文件的用途**：凡是"玩家能建、但这个 mod 画不出来或者画不对"的建筑，
> **都记到这里**，不要只留在对话或日志里。
>
> 面向发布：拿到这个 mod 的人应该能在这里查到"为什么我这里没显示"，
> 而不用来问你。
>
> **最后更新**：2026-09-27 凌晨

## 一、画不出来（映射写成 `"-"`，那个位置是空的）

| 建筑 | 类型名 | 为什么画不出来 | 状态 |
|---|---|---|---|
| **观赏笼** | `DisplayCharacter` | 它**不是一个网格**，而是用「8 个单位方块 + 8 根柱子」**缩放拼出来**的。我们的蓝图每件建筑只存"一个网格 + 一个朝向"，画出来就是一根超长的柱子 | 等**待办 3**（组件的相对变换）|

### 详细说明：观赏笼

- 英文 id 是 `Viewing_Cage`，代码是 `DisplayCharacter`（paldb.cc / gamersky 可查）
- 注册表里搜 `Viewing` / `Display` **零命中**；搜 `Cage` 只有**野外盗猎团**的
  `SM_PalCage` 和海盗据点的 `/Stage/b05/PiratesAge/SM_Cages_*` —— **都不是玩家能建的**
- 该 Actor 的实际组件：`SM_PalBox_Pillar` × 8 + `Cube_LowHeight` × 8 + `SM_Pointer` × 1
- **结论**：想画对，必须知道每个子件的**位置和缩放**（见待办 3）

> ⚠️ **别用 `SM_PalCage` 顶替** —— 那是盗猎团关帕鲁的世界道具，玩家用不了。
> 我犯过这个错，玩家一眼就看出来了。

## 二、画得出来，但**只画出了建筑的一部分**

> **2026-09-28 补充（伐木场 / 采石场）**：
> 这两个建筑在游戏里是**多件拼装**，而本模组的蓝图每件只记"**一个网格 + 一个朝向**"：
> * 伐木场 `StationDeforest2` = `SM_Loggingcamp_Tree` + `_Fence` + `_Acce`
> * 采石场 `StonePit` = `SM_StonePit_SM_StonePit_RockA/B/C` + `_Fence` + `_Acce`
> * 金属采矿场2 `CopperPit_2` **与采石场共用同一套外观资产**（`StonePitLarge`）——
>   所以两者看起来会很像，这不是 bug。
>
> 现在覆盖表里给的是**主件的单网格近似**（伐木场用那棵树、采石场用岩石组），
> 会缺掉围栏/附属件。**完整拼装要等「待办 3：组件的相对变换」**。
> 觉得近似不够好看，可以改 `Scripts\pwpr_meshmap.json`（你的表，部署不覆盖）。

这些类型**不会**列进"画不出来"，但形状可能不完整。原因是同一个：
建筑由多个子件拼成，而我们只能给出网格列表，给不出各自的位置/缩放。

| 建筑 | 类型名 | 情况 |
|---|---|---|
| 简约门 | `SF_DoorWall_02` | 已用**多网格映射**补成 门框 + 左门扇 + 右门扇 ✅ 完整 |
| 帕鲁装扮机 | `CharacterSkinChange` | 已补成 底座 + 雕像 ✅ 但**雕像固定是粉猫**（那件可能是按当前帕鲁动态换的）|
| 观赏笼 | `DisplayCharacter` | ❌ 见上表 |

**判断方法**：如果某件建筑投影出来"缺了点什么"，先看 `pwpr_meshes.txt`
第 5 节里这个类型有几个组件 —— 多于一个就说明它可能是装配体。

## 三、**看起来一样，但那是游戏设计**（不是 bug）

| 现象 | 原因 |
|---|---|
| 所有作物农场长得一样（野果/小麦/番茄） | Palworld **所有作物农场共用田垄网格 `SM_FarmGround`**，品种差异在"作物"上，而作物不是挂在建筑 actor 上的 |
| 三个"高等文明"工厂一模一样 | 游戏自己的组件数据就是同一个网格 `SK_PalSphereFactoryFuturistic` |
| 骨骼网格建筑（后期工厂、磨石…）**没有动画** | 骨骼网格显示的是**绑定姿势**；对静止的机器观感正常 |

## 四、能力边界

| 限制 | 原因 |
|---|---|
| 分层通常只有 2–3 层 | **Palworld 的墙和地基是同一个 Z**，只有真正叠楼才有更多层 |
| 联机时可能不完整 | 客户端可见性受网络相关性裁剪；本 mod 面向**单人 / 自建服务器** |
| 骨骼网格每件一个组件 | 不能实例化；实例很多时组件数会涨（有 `ghost_max_instances` 上限）|

## 五、怎么往这里加新条目（给以后的我 / 维护者）

**发现"某件建筑没显示 / 形状不对"时的流程**（完整版见 `README.md` 第 10 节）：

1. 站到那件建筑旁边按 `Y` 重新采集
2. 看 `Scripts\pwpr.log` 的 `网格解析: … 未解析 N` 和 `Scripts\pwpr_meshes.txt`：
   - **第 2 节** —— 哪个类型匹配到 `-`
   - **第 3 节** —— 每个类型为什么读不到（含"朝向差"）
   - **第 5 节** —— ★ **反向取证**：从网格组件反查「建筑类型 → 网格」，
     直接给出可以粘贴的映射条目
3. 能查到网格 → 写进 `Scripts\pwpr_meshmap.json`（用户表），按 `F8` 生效
4. **查不到、或者查到了但明显不对** → **在本文第一或第二节加一行**

**写入这里的判据**（重要，别把"我没查到"和"游戏没有"混起来）：

| 情况 | 记哪里 |
|---|---|
| 游戏**没有**可读的独立网格（组件是图元拼的 / 只有占位块） | **第一节**，映射写 `"-"` |
| 有网格但只拿到一部分（子件装配体） | **第二节** |
| 是**游戏设计**导致的"看起来一样" | **第三节** |
| 只是我们漏了映射（能查到正确网格） | ❌ **不进这个文件** —— 直接补映射表 |

> **一条硬规矩**：宁可写 `"-"`（不画）也不要画一个"看起来像"的。
> 画错的东西不会报错，只会静默地骗人 —— 而且会被玩家一眼看出来。

## 六、屏幕提示（游戏内文字）的功能限制 —— 2026-09-28 补

> 功能怎么实现的、怎么排查、配置在哪：见 `docs\屏幕提示功能.md`。

| # | 限制 | 说明 / 绕法 |
|---|---|---|
| 1 | **颜色不能自定义** | `_G.FLinearColor` / `_G.FSlateColor` 都**没有暴露**给我们，构造不出 `SetColorAndOpacity` 要的结构体。所以"正常/出错用不同颜色"目前只能靠**换控件类**（改配置 `notify_widget_class_name`）实现 |
| 2 | ~~"回标题 → 重进世界"后第一次操作可能闪退~~ → **已修（2026-09-28）** | 根因：上个世界的对象已被销毁，而 `Util.usable()` / `IsValid()` 会**撒谎**（返回 true），于是拿废控件去 `SetText` → 访问违例。**修法**：用 **`LoadMapPre` 钩子**当"权威信号"——引擎说"要换地图了"时**只清 Lua 引用、一个引擎接口都不碰**（`Ghost.forget` + `Hud.drop_world_refs`）。轮询世界标记降级成纯诊断（它抖动时曾把正常放置搞坏：每次 0 件）。配置 `hook_load_map_pre` **默认 true，不要关**（关了闪退会回来） |
| 3 | 只有**一种**样式 | `notify_error_class_name` 留空 ⇒ 正常/出错共用一条提示。想区分就填另一个控件类 |
| 4 | 提示**不排队** | 新提示直接覆盖旧提示（同时旧定时器作废，保证新提示拿到完整时长） |
| 5 | 需要用"游戏自带的独立浮层控件" | 复制**列表项**（如 `WBP_Notice`）会"属性全对却什么都看不见"—— 列表项的布局依赖父容器 |
| 6 | 实测能显示但不适合用的候选 | `WBP_Ingame_Sleep_C`（睡眠框，居中大框）、`WBP_IngameSmesTop_C`（长得像"升级提示"） |

### 绝对禁用的接口（实测崩游戏，别再试）

| 接口 | 现象 |
|---|---|
| `KismetSystemLibrary:PrintString` | Shipping 构建里函数体被编译掉，反射还在 ⇒ 调用即崩 |
| `PlayerController:ClientMessage` | 调用即崩（`EXCEPTION_ACCESS_VIOLATION`）—— 已标 `never_call`，探测都拒绝调它 |
| `ForEachFunction` / `ForEachProperty` / `ForEachUObject` | 调用即崩 —— 已写进检查器第 11 项硬拦 |

> **判据**：`Util.usable=true`、"反射里有"、"签名公开"**都不等于能安全调用**。
> 只有**实机调用证据**才算数。

## 七、**换存档投影缺件** —— 2026-09-28 已修（但**旧蓝图需要重采**）

| 项 | 说明 |
|---|---|
| 现象 | 在存档 A 采集的蓝图，拿到存档 B 投影时**缺件**（有些建筑不显示） |
| 原因 | 蓝图原来只存网格**短名**，投影时靠"运行时注册表"查路径，而注册表只包含**当前已加载**的资产；换存档后蓝图里的大量资产没被加载 ⇒ 查不到 ⇒ 跳过不画 |
| 修法 | 采集时把网格的**完整资产路径**写进蓝图（新字段 `mesh_path`），投影时直接 `LoadAsset(路径)` —— 与"当前加载了什么"无关 |
| **你需要做的** | **旧蓝图请回到源存档重新采集一次**（它们没有 `mesh_path`）。重采后跨存档投影才完整 |
| 自查方法 | 投影后看 `pwpr.log` 的报告行：`缺网格: <类型> N 件` —— 它会列出还缺哪些类型；能查到资产的话把映射补进 `Scripts\pwpr_meshmap.json` 即可 |

## 八、★ **建造吸附**（手拿建筑放下时吸到投影上）—— 2026-09-29

> 权威文档: [`docs\建造吸附.md`](../../docs/建造吸附.md)（原理 / 配置 / 日志排查 / 首次实测）。

| 限制 | 说明 / 怎么办 |
|---|---|
| **预览方块不会跟着吸** | 那个半透明预览是游戏自己的、**Lua 抓不到也改不了**（实测见 `docs\踩坑记录.md` §3f-7）⇒ 只有**放下去的那一件**精确落位。看着预览没动是正常的 |
| **只在"放下那一刻"生效** | 不是"一边瞄一边自动对齐"。想做"放之前就看见会落在哪"需要我们自己画高亮标记（下一步的增强项） |
| **`align` 模式要类型 + 距离都对得上（但有兜底）** | 太远（默认 >**30 米**）⇒ 不吸；差得比 **5 厘米**还准则**完全不插手**。**类型对不上时会用"放宽阈值"**（`buildsnap_type_loose_cm`，默认 150 厘米）吸最近的任意类型记录，并**自动记住这个 id 对应的类型**（实测: 游戏叫 `Wooden_foundation`、蓝图里叫 `Wood_Foundation`）。**默认朝向跟投影**（`buildsnap_rot_tol_deg = 180`）、**高度用游戏给的**（`buildsnap_snap_z = false`，2026-09-29 因水面地基卡死事件改回）|
| **类型实在对不上就别用 `align` 的单靠名字** | `blueprint` 模式的类型由投影决定，但它要求**先学到游戏 id**（先用 `align` 盖一件同类的，日志里会出现 `★ 学到映射`） |
| **`blueprint` 模式未完成 / 暂不可用** | 蓝图类型是**类名**、游戏认的是另一套 id（`Wood_Foundation` ≠ `Wooden_foundation`）⇒ 必须先"学到"才发得出去；材料还按**投影那件**算。设成它会进那条没做完的路（日志/屏幕会告警）⇒ **请用 `align`**。只服务于它的两个键已归到配置第 3 组（`docs\配置说明.md` 1.3）。 |
| **`blueprint` 模式不看你在建造菜单里选了什么** | 材料消耗按**投影那一件**的类型算；材料不够时游戏会按它自己的规则拒绝（屏幕上会提示「素材不足」） |
| **放好的那一件还会闪吗** | 不会: "放上去的那一件立刻从投影里消失"（精确通道，**始终有效、不枚举**）；按 `K`/`L` 重放投影时还会**扫一遍**把之前放过的件也标成不显示（`ghost_hide_enum = true`）。<br>⚠️ **"拆掉后自动恢复"默认关**（`ghost_hide_scan = false`）：那条周期性扫描会在你拆完建筑后去读 `level.Actors` 里那个还没被清掉的死对象 ⇒ **原生访问违例**（本机崩过两次）。拆掉后**按 `K` 收起再放一次**即可重新画出来。 |
| **拆除恢复最慢要等 ~8 秒** | 恢复靠"兜底全扫"（每 8 秒重读一遍关卡建筑列表）。原来那条"每 2.5 秒查引用"的快路径**已默认关闭** —— 它会对已被摧毁的 actor 调 `Util.valid()`，实测**崩过一次游戏**（原生访问违例，pcall 抓不住），而且它本来就报"全部存活"、根本不灵。 |
| **放下时不会再重灌整个投影了** | 吸附时就知道"往哪一条记录放" ⇒ 只重灌受影响的组（十来件实例）。全扫（读本关卡建筑列表）只在**每约 7.5 秒**的慢路径上跑一次，用来发现"拆掉了" |
| **它动的是游戏自己的放置请求** | 出问题（摆放异常/放不下去）先把 `buildsnap_enabled` 改成 `false` 按 `F8`；想零风险观察就用 `buildsnap_dry_run = true` |
| **★ 吸附后的高度不被允许时，它会自己挪投影高度**（行为，不是 bug）| 现象: 你放下后**那一块没建出来**，同时屏幕弹提示、日志写 `[bsnap] ★ 高度自适应: … 投影 Z 偏移 +23 厘米`，**投影整体上下移动了一下**。<br>**为什么**: 水面/地形上，游戏认的"可放置高度"和投影记录的高度常常差几十厘米；我们按投影高度发出去就被游戏拒。⇒ 这时把它记成"高度差 `dz`"，**整份投影挪 `dz`**（记进位置记忆）⇒ **再放一次就用修正后的高度**，高度继续跟投影。<br>**想手动压回去**: 方向键 / 小键盘 `9`、`3`（`F9` 切"移动"模式）微调，或按 `H` 把投影拉回脚下重放。<br>★ 另外: **高度差 ≤ 人物半高（实测 88 厘米）时不判高度**（半径闸/修正量上限按平面距离判）—— 避免"站得很准却吸不上"。|
| **大搬运（超过 `buildsnap_safe_cm`）会被原样放行**（该键**默认 0 = 不限制**）| 2026-09-29 实测: 水面地基上"拦下原请求 + 按投影坐标**重发**"曾让游戏**卡死 1 次、崩 3 次**（`docs\踩坑记录.md` §68）。<br>**这个键不是"防崩手段"**: 后来实测有一次修正量只有 **44.9 厘米**照样崩 ⇒ 真正的修复是 **`buildsnap_defer`（重发排到下一帧，默认开）**，而不是限制修正量。<br>⇒ `buildsnap_safe_cm` 只留给"想保守一点"的人（填多少就只吸多少以内）；默认不限制。|
| **不绕过游戏的合法性校验** | 如果投影那个位置本来就不合法（悬空/重叠），游戏会拒绝 —— 我们不干预，也不会重试 |
| **多人游戏未验证** | 逻辑挂在"客户端请求放置"上；联机时服务器可能另有校验，**没测过** |

## 九、**投影对齐**（把整个投影挪到已有建筑上；按 `U`）—— 2026-09-29

> 吸附 = 把投影**一步对齐**到附近真实建筑的位置（改的只是投影偏移/朝向，**不动蓝图数据**）。
> 算法与实测见 `docs\踩坑记录.md` §35、`docs\项目状态与路线图.md` 待办 2。
> **触发时机**：按 **`U`**（键名配置 `snap_key`；**没有小键盘的键盘也能按**）。
> 放下投影时的自动对齐（`snap_on_place`）**默认已关** —— 想叠图对比再打开。
> ★ **不会**在"挪投影"时自动吸 —— 那会卡顿且和手动微调打架（理由见 §42）。

| 限制 | 说明 / 怎么办 |
|---|---|
| **要靠"原建筑还在场"** | 它拿附近**真实建筑**当参照。图纸是别的存档采的、或现场根本没有那些建筑 ⇒ **吸不了**。这时日志会明确说"附近没有同类型的建筑"，投影**一动都不动** |
| **基地里全是重复件时定位不了** | 合成数据实测: 只有地基+墙（没有任何独特件）的基地会吸到"**错几格**"的位置 —— 这种布局**信息本身不足以定位**。现实基地总有帕鲁终端/机器/箱子这类独特件，所以正常情况没事 |
| **匹配率低 / 有歧义时会明说** | 屏幕上那句会带 `（匹配 46%，看一眼）` 或 `（有歧义，看一眼）`。**这不是报错，是算法在说"我不确定"** —— 请用眼睛确认投影和真实建筑是否重合；不合适就按 `H` 把投影拉回脚下（偏移清零）、再按 `U` 重来 |
| **你站得离基地中心越远，越需要调阈值** | 投影原点是"玩家脚下"，所以偏差≈你到基地中心的距离。超过 `snap_radius_cm`（默认 20 米）就配不上对了 ⇒ 把 `snap_radius_cm` 调到 4000~6000 |
| **朝向差太多时也可能配不上** | 先用方向键/`+`/`-` 转到大致对（或保持 `snap_yaw_search = true` 让它自己找） |
| **不会让"多件拼装"变准** | 伐木场/采石场那类多网格近似还是待办 3 的事（见本文第一节） |
| **只读位置/类名/朝向，不读网格资产** | 老存档里"游戏更新后已删除"的网格是野指针，碰它会崩（`docs\踩坑记录.md` §29）⇒ 故意不读 |
| **纯网格对齐（对齐到游戏建造网格）还没做** | 步长正在**就地实测**（吸附时日志里那行 `观测到的坐标间隔`），拿到数据后再做 |

## 六、行为上的取舍（2026-09-29 定稿，不是 bug）

| 取舍 | 现象 | 为什么这样定 |
|---|---|---|
| **`H` 那一份不跑扫描** | `H` 之后拆掉某件，投影不会自动恢复 ⇒ 按一次 `K` 让它重新核对世界 | 扫描「认领」在规则网格上有歧义（别处已建的件平移整数格后会落在新位置上）⇒ 新位置的投影会莫名缺件 ✗ |
